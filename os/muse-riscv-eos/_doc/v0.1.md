# embed-os v0.1 — 功能描述

- 版本：0.1.0（首個可開機多工版本）
- 目標：RISC-V 32-bit IMAC（`riscv32imac-unknown-none-elf`），QEMU `virt` 機器
- 語言：Rust（`no_std`、`no_main`，零外部依賴），全 M-mode 執行
- 日期：2026-09-19
- 驗證：`./test.sh` 48 項全綠（靜態 26＋動態 22）

## 1. 總覽

最小 bare-metal 多工嵌入式 OS：開機後啟動 3 個任務，由 100 Hz
機器時鐘中斷搶佔排程（round-robin），另有 UART 互動 shell。
無 heap、無 S-mode/U-mode、無檔案系統——刻意保持最小，以展示
開機、trap、時鐘、上下文切換四件核心機制。

## 2. 開機（`_start` → `rust_main`）

1. `la sp, _boot_stack_top` 切到 8 KiB boot 堆疊
2. 清 `.bss`（`_sbss.._ebss`）
3. `call rust_main`：初始化 UART、印 banner 與 memory map、
   建立 3 個任務、`mtvec=trap_entry`、`mscratch=任務0 frame`、
   規劃第一次時鐘中斷、開 MIE，經 `enter_first_task` 用 `mret`
   進入第一個任務（此後不再回來）

## 3. 主控台（`src/uart.rs`）

- QEMU virt NS16550A，基址 `0x10000000`，polling（不開 UART 中斷）
- `print!` / `println!`：以 `csrrci/csrw mstatus` 開關 MIE，
  單 hart 下每行輸出原子完成；避開 spinlock，也避開
  「持鎖時被時鐘搶佔」死結
- `\n` 自動轉 `\r\n`

## 4. Trap（`trap_entry`＋`rust_trap`）

- asm 入口：`csrrw sp, mscratch, sp` 換到目前任務的 `TrapFrame`，
  存 x1–x31（x2 經 mscratch 間接存）、`mepc`、`mstatus`，
  再把 `sp` 切到 8 KiB **專用 trap stack** 後 `call rust_trap`，
  回傳新 frame 指標，還原後 `mret`
- 分派：
  - machine timer（mcause `0x80000007`）：`TICKS+=1`、重設
    `mtimecmp`、round-robin 切到下一個 alive 任務
  - machine software（`0x80000003`）：清 msip，視同 yield
  - machine external（`0x8000000B`）：UART 用 polling，無事可做
  - M-mode ecall（`0xB`）：見 §6 系統呼叫，`mepc` 前進 2 或 4 bytes
   （依壓縮指令判斷）
  - 其餘 fault：印 `mcause/mepc/mtval`＋32 個暫存器 dump；
    shell（任務 0）出錯則關 timer 中斷後 `wfi` halt，
    其他任務出錯則標記死亡並繼續排程
- 防呆：fault dump 前 `mie=0`；`IN_TRAP_DUMP` 重入保護，
  dump 中再 fault 就安靜 halt（防巢狀 trap 洗版）

## 5. 時鐘

- CLINT：`mtime` `@0x0200BFF8`、`mtimecmp0` `@0x02004000`，
  timebase 10 MHz；`TICK_INTERVAL=100000` cycles＝10 ms，即 100 Hz
- `mtimecmp` 寫入順序：hi=`0xFFFFFFFF` → lo → hi（防假中斷）
- `TICKS`（u64）只在 trap 內寫；任務經 syscall 讀，無 tearing 問題

## 6. 系統呼叫（M-mode 內 `ecall` 示範）

| a7 | 名稱 | 說明 |
|----|------|------|
| 0 | yield | 自願讓出，切下一個任務 |
| 1 | putc | a0 低 8 位元送 UART（trap 內直寫，不取鎖） |
| 2 | getc | 非阻塞讀；無資料回 `0xFFFFFFFF` |
| 3 | ticks | a0/a1 回 64 位元 tick（lo/hi） |
| 4 | taskid | a0 回目前任務 id |

## 7. 任務（各 4 KiB 核心堆疊＋一個 `TrapFrame`）

| id | 名稱 | 行為 |
|----|------|------|
| 0 | shell | UART 互動 shell（§8），無輸入時 `yield` |
| 1 | blink | 每 200 tick（2 s）印 `[blink] count=N tick=T` |
| 2 | fib | 反覆算 fib(24)，每 300 tick 印 `[fib] iter=N fib24=46368 tick=T` |

- 初始 `mstatus=0x1888`（MPP=M、MPIE=1、MIE=1），`mepc`＝任務函式，
  `ra=task_exit`（任務若返回就印訊息後 parking）
- `fib24` 恆為 46368（F₂₄）是刻意設計的「金絲雀」：
  確定性計算每 10 ms 被搶佔一次，值不變即證明上下文切換正確；
  `iter` 為累計計算次數
- `ps` 的 `runs` 欄是各任務被排入次數（含 ecall yield），三者應大致相等

## 8. Shell 指令

| 指令 | 功能 |
|------|------|
| help | 列出指令 |
| info | hart、版本、各區段位址、時鐘頻率、UART 位址 |
| ps | 任務表（id、名稱、alive、被排入次數，`*`＝目前任務） |
| ticks | tick 數＋uptime（秒） |
| echo `<text>` | 回顯 |
| yield | 自願讓出並印任務 id |
| whoami | 印目前任務 id（經 syscall 4） |
| timer | 原始 `mtime`／`mtimecmp`／ticks |
| fault | 執行 `unimp` 觸發非法指令 trap（展示 dump 後 halt） |
| poweroff | 寫 SiFive test 裝置 `0x100000` 使 QEMU 正常退出（rc=0） |
| clear | ANSI 清屏 |

行編輯：128 位元組緩衝、echo、Backspace（`0x08`/`0x7f`）、
`\r`／`\n` 結束一行；無輸入時讓出 CPU。

## 9. 記憶體配置（RAM 128 MB @ `0x80000000`）

| 區段 | 內容 |
|------|------|
| `.text` | `_start`、`trap_entry`、`enter_first_task`、核心程式 |
| `.rodata`／`.data` | 字串、`TASKS`（frame＋堆疊×3） |
| `.bss` | `TICKS`、`CURRENT` 等 |
| boot stack 8 KiB | `rust_main` 執行用 |
| trap stack 8 KiB | `rust_trap` 專用（§10 的教訓） |

實測 footprint：text＋data＋bss ≈ 32 KB；ELF ≈ 70 KB。
關鍵位址：UART `0x10000000`、CLINT `0x02000000`、
SiFive test `0x100000`。

## 10. v0.1 開發中修掉的 bug（已進測試防迴歸）

`trap_entry` 最早直接以 `sp = TrapFrame` 呼叫 `rust_trap`，
Rust 呼叫堆疊從 frame 位址往下長，蓋掉相鄰 `.data`：
`TASKS[0].name` 被改寫成 `0x88000000`，`ps` 一印任務名就
`load access fault (mcause=0x5)`，而 fault-dump 又讀壞掉的名字，
造成巢狀 trap 洗版（約 5 MB 的 `0xFF`）。
修正三件套：獨立 trap stack、fault 路徑先 `mie=0`、
`IN_TRAP_DUMP` 重入保護。`test.sh` 的 B5（恰一次 FATAL）與
B6（halt 後輸出 < 4 KiB）即為此迴歸測試。

## 11. 建置／執行／測試

```sh
cargo build            # dev；--release 可另編 release 版
./run.sh               # QEMU 開機（--release 跑 release 版）
./test.sh              # 48 項自動測試，約 30 秒，ALL GREEN 才算過
make disasm | make size # 反組譯／量測（需 riscv-gnu-toolchain）
```

需求：Rust nightly（含 `riscv32imac-unknown-none-elf`）、
`qemu-system-riscv32`、`timeout`；`riscv64-unknown-elf-{nm,objdump,size}`
僅靜態檢查用，缺了會 SKIP 不會 FAIL 動態測試。

## 12. 已知限制（非 bug，留待後續版本）

- 全 M-mode，無使用者態／系统呼叫隔離（ecall 只是 trap 示範）
- 無巢狀中斷、無 PLIC（外部中斷直接忽略）、UART 純 polling
- 無 heap、無鎖（單 hart 靠開關 MIE 互斥）
- 任務數固定 3、堆疊固定 4 KiB、無優先級
- shell 單行 128 位元組上限、無歷史記錄、無 Tab 補全
