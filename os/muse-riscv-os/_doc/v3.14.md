# muse-riscv-os v3.14（主線：guest TLS PKI —— TLS 1.3 client-only）

## 0. 動機

`plan3.x §6` 把 TLS 列為非目標（guest handshake 太重；user-net 只信本地）。
v3.4/v3.11 的信任鏈停在 `sha256 + Bearer` 明文——防損壞不防竊聽/偽造 registry。
本版把傳輸補上：guest 側真正的 TLS 1.3 client + X.509 鏈驗證（完整 PKI 語義，
最小套件形狀）。

範圍誠實聲明：不是通用 TLS（單 cipher suite、client-only、無 resumption；
RNG/牆鐘是 test-grade，見 §1）。ECDSA P-256 而非 Ed25519——複用既有 SHA-256，
不引入 SHA-512（`plan3.x §16` 的 ed25519 假設在此修正）。

## 1. 語義

- TLS 落點（userspace，kernel 只傳 bytes）：
  `ctr/wget → guest-tls（handshake/record）→ socket(TCP) send/recv`。
  kernel 不動 TCP（`net/tcp.rs`、`net/mod.rs` 零改），只加兩個 syscall：
  - `SYS_GETRANDOM = 58`：guest 隨機源。virt 無 RNG 硬體，取
    `timer::ticks ^ MAC ^ per-call counter` 混合（test-grade；真 virtio-rng 另立版）。
    用途唯一：ECDHE ephemeral + ClientHello random（suite outcome 確定，bytes 可漂）。
  - `SYS_SETTIME = 59`（或 build-time epoch + uptime 合成牆鐘）：
    virt 無 RTC（`syscall.rs:52`）。registry TLS 握手前先明文取
    `GET /time`（host epoch 秒）→ guest 存 `boot_epoch`，之後
    `wall = boot_epoch + uptime_ms/1000` 供證書 expiry 檢查。測試證書 10 年期，
    容忍啟動時差（±1 天內不擋；大偏差 loud 拒絕）。
- `guest-tls` crate（`user-lib/guest-tls/`，workspace member——原定
  standalone，但 member→standalone 的 path 依賴被 cargo 拒絕
  （multiple workspace roots），故納入 workspace（仍可
  `cargo publish -p guest-tls`；與 guest-args/guest-fmt 的 detached
  慣例不同，原因在此），
  _publishable_；in-tree path 依賴）：
  - `no_std + no_alloc`（core-only，調用方供靜態 buf；對標 `Sha256` 風格）。
  - 單套件：`TLS_AES_128_GCM_SHA256 + X25519 + ECDSA-P256-SHA256`。
    已落地：HMAC-SHA256、HKDF-SHA256、AES-128-GCM、X25519、P-256
    （ECDH + ECDSA verify）、最小 DER/X.509 子集（欄位白名單解析；
    SAN-IP 驗證 + pinned root，全鏈自 openssl 向量測起）。
  - API（傳輸無關純函數，I/O 留給調用方；`wgets` 側組裝）：
    `tls13::{build_client_hello/parse_server_hello/schedule_hs/
    schedule_ap/seal/open}` + `x509::verify_chain`；握手狀態機不碰 kernel。
  - host-tests：RFC/node/openssl 三源向量；`cargo test -p guest-tls`
    進 fast gate；另有對 `openssl s_server` 的端到端互通測試。
- `wgets`（新 binary，用戶態 3 touches）：`wgets <host> <tlsport> <path>
  <outfile> [token]`（明文 `:8091/time` 對鐘 + `/rootcert` TOFU 進
  `/pkg/rootcert`；SNI 省略——IP-literal server，認 SAN-IP；
  失敗沿用 `wget FAIL (<reason>)` 家族，成功行是 distinct 的
  `wgets PASS <basename>`）。
- registry（`img_registry.py`）：+8443 TLS 監聽（host `ssl`，TLS 1.3
  單套件；ECDSA P-256 測試鏈 root → leaf，一次生成、落
  `tools/registry-state/` 跨重啟沿用、私鑰不進版控；
  明文 8091 保留，舊測項不動）。`GET /time` 明文（供 guest 對鐘，僅此一路明文）。
- `ctr install` over TLS：**本版不動**（v3.15 接 `ctr installs`；本版只證明
  guest TLS 取包鏈路：`wgets` 抓 manifest/tar + `sha256` 驗 + 手動解包跑）。

## 2. suite（確定性設計）

```
wgets 10.0.2.2 8443 /pkg/hello/1.0/manifest /tmp/m1  → wgets PASS manifest
wgets 10.0.2.2 8443 /pkg/hello/1.0/hello.tar /tmp/h1 → wgets PASS hello.tar
# 偽造 registry（錯 root，自簽）→ wget FAIL（verify），marker 沿用，不新增
```

- test.sh +2 項（run1）：`wgets PASS manifest`、`wgets PASS hello.tar`
  （distinct marker：`check` 是 presence 制，同字串斷言兩次無意義；
  單次 `print` 整行，console-lock 單 write 紀律不變）。
- 手動：SNI 錯名、過期 cert（調 `/time` 灌錯鐘）、明文 8091 照舊。

## 3. 非目標（→ v3.15+）

- `ctr installs`（install 全鏈 TLS）、TLS session resumption、ALPN、client cert。
- 真 RNG（virtio-rng device + `-device` 接線）、真 RTC/NTP 對鐘。
- Ed25519/SHA-512（`§16` 原假設；P-256 已夠用，不再追）。
- Cipher agility（多套件協商）、證書吊銷/OCSP、SNI 多域。

## 4. 驗收

- `./test.sh` 全綠（120+2=**122 項**），零 `PANIC`/`FAIL`，連跑 2 輪。
- fast gate 先行：`cargo test -p kernel -p host-tests -p mkfs -p user-lib`
  + `guest-tls` standalone `cargo test`（RFC 向量全綠才進 QEMU）。
- 舊測項零退化（重點：明文 8091 路徑逐位元同舊；kernel TCP 零改）。

## 5. 落地備註（實作與 spec 的差異 + suite 教訓）

- syscall 編號：`SYS_GETRANDOM = 58` 依 spec；牆鐘拆成
  `SYS_SETWALL = 59` + `SYS_GETWALL = 60`（spec 寫 `SYS_SETTIME`，
  實作改名以區別語義：set 是一次性 epoch，get 是 epoch + uptime）。
- `USER_STACK_PAGES` 8 → 16（spec 未提）：`ctr upgrade_one` 單 frame
  ~29.5KB，32KB 棧在 `pkg_db_ver` 序言確定性 page fault（三連同
  sepc/stval）；64KB 恢復 2 倍餘量。`wgets` 用 `mmap` 放 ~17KB
  record buf，不碰此問題。
- `test.sh` stub 存活期 §6 → §11：stub-less 的 bootB 要 >280s 走完
  autorun 前綴（每個 doomed TCP connect 燒 500-spin retry；v3.14 多
  6 個），有 stub 只要 36s。§11 證的是 fs-local（replay + verify），
  stub 只加速無關前綴，故留到 §11b 後再殺。
- prompt-feeder 240 → 360（§§8/9/11a/11b），`TO3/TO4` 360/300 → 480，
  §11b poll 280 → 420：host load ~5.8 時 stubbed autorun 也要 ~250s；
  blind-fed 命令被 nibble 必 FAIL（見過 `crash FAIL (no file)`）。
  量測基數：stubbed 36s（load ~3）→ 250s（load ~5.8），非 wedge
 （兩次 stub-less §11b 都穩定推進到 ctr-volc 段，無 PANIC）。
- `test.sh` QEMU 側改走 `8081`（`web_fetch.py` 同步；`run.sh` 維持
  `8080`），避開 host 埠衝突。
