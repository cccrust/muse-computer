# muse-riscv-os v0.12（實作中，主線：測試框架 clean-halt 覆蓋）

方向：純 `test.sh` 擴充（run4/run5），不動 kernel/user。目的：證明正常關機路徑（dirty flag 清除），為未來的 write-back 鋪路（見 v0.10 §4）。

## 1. run4：同映像再次 clean halt

- 與 run3 同形（管線 stdin），`(sleep 18; printf 'halt\n')`，25s 窗口。
- 18s 的依據：autorun 約 15s 到 prompt；即使 prompt 還沒好，輸入也會在 UART ring（256B）裡等它讀，不丟失。
- 斷言：`halting` + 無 PANIC。

## 2. run5：clean halt 後重啟，mount 不該 fsck

- 與 run1 同形（`< /dev/null`，25s）。
- 斷言：`disk mount ok` 出現 + `fsck: bitmap rebuilt` **不出現**（absence assertion，本框架首見）+ 無 PANIC。
- 原理：run4 的 `halt` 走 `SYS_SHUTDOWN` → `set_dirty(false)`；run5 mount 見 dirty=0 即跳過 bitmap 重建。反之 run1→run2（timeout 砍掉，未正常關機）必重建——兩條路徑各有覆蓋，不互相取代。

## 3. 非目標

- write-back 本體（仍不做；但本版之後，write-back 的正確性已可測：run4-halt → run5-assert-READ）。
- 縮短套件時間（+2 boots，約 +50s，可接受）。
