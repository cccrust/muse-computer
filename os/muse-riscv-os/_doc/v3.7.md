# muse-riscv-os v3.7（主線：registry 常駐化——publish 上架）

## 0. 動機

v3.0–v3.6 的 registry 是測試樁：包寫死在代碼裡，想加第七個包
只能改 stub 重啟。日常可用的第一步是讓 registry 變成服務：
活著的時候能收新包，重啟後還在。本版只做上架與持久化，
不做包的增刪改查 UI（那是將來）。

## 1. 語義

```
pkgbuild.py --crate DIR --pkg NAME --version VER --bin BIN \
    --registry http://127.0.0.1:8091 --token admin-token \
    [--add arc=host ...] [--depends "..."]
```

- 磁碟佈局：`tools/packages/<name>/<ver>/{manifest,<layer>.tar}`
  （host 目錄；運行時數據，gitignore，只留 `.gitkeep`）。
  重啟即上架（啟動掃磁碟）。
- 上傳：`PUT /pkg/<name>/<ver>/<file>`（file = manifest 或單層
  tar 名），頭 `Authorization: Bearer <ADMIN>`（stub 常量
  `admin-token`，toy-auth，寫死）。成功 200，
  `published <name> <ver>`；缺/錯 token → 401；名/版不合
  `[A-Za-z0-9._-]` 或超長 → 400；body 超限
  （manifest 4K，tar 2M）→ 400。寫磁碟 + 即時註冊路由 +
  重生成該包 index（內存與磁碟一致，不用重啟）。
- index：磁碟包的版本列表啟動時生成、PUT 後增量更新；
  與啟動現包（hello 等）的靜態 index 行為一致（guest 看不出差別）。
- 新包預設公開（secret 式私包是 stub 寫死的特例；publish 的
  `--private` 以後再說）。
- guest **零改動**：install 走同一套路由（上架即裝得到，
  就是證明）。已發布包的覆寫 PUT：允許（冪等，後寫贏；
  刪包不提供——刪磁碟 + 重啟 registry，寫死在這）。
- 非目標：`--private` 上架、刪包 API、多 registry、配額、
  TLS（v3.4 已判）、包簽名上傳時驗（guest 下載驗，沿用）。

## 2. suite（確定性設計：上架即裝）

test.sh 在 stub 啟動後、QEMU 開機前加一步（registry 活著才能 PUT）：

```bash
python3 tools/pkgbuild.py --crate tools/pkgdemo --pkg pubdemo \
  --version 1.0 --bin fortune \
  --registry http://127.0.0.1:8091 --token admin-token || PASS=0
```

（`--pkg pubdemo` 但 `--bin fortune`：包名與二進制名脫鉤的
第一次實證；`/bin/fortune` 當時是空的——v3.2 段刪過了。）
autorun（volume 段後，db 乾淨）：

```
ctr install 10.0.2.2 8091 pubdemo   → pkg-installed pubdemo 1.0
ctr list                              (PKGLS pubdemo 1.0 行出現，不斷言）
fortune hello-from-pub              → fortune-sez hello-from-pub
ctr remove pubdemo                  → pkg-removed pubdemo
```

- test.sh +3 項（run1）：上列三個 marker。上架失敗本身
  `|| PASS=0` 直接炸，不需要 marker。
- 手動：錯 token PUT（401）、重啟 registry 後包還在（磁碟證明）、
  覆寫 PUT（後寫贏）。

## 3. 非目標（→ v3.8+）

`--private`、刪包 API、多 registry 聯邦、磁碟配額、上架時驗簽。
