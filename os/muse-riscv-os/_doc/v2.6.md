# muse-riscv-os v2.6（主線：容器命運共同體——cgroup-kill）

## 0. 動機

v2.4 的 `stop` 只殺 pid1：孫進程過繼給 init 繼續活（寫死在 v2.4.md §3）。
真容器的語意是 fate-sharing——停一個，整組跟著走。本版補上：
每個容器自帶 cgroup，`stop` 按組殺。CPU share、netns 照舊往後。

## 1. per-container cgroup（user 側編排，內核只多一個殺器）

- `ctr run[-d]`：root 探測通過後，父 `cgcreate(0)`（unlimited；
  parent 記成調用者所在組，層級可查）→ fork → 子第一件事
  `cgenter(new)`（chroot 之前；失敗即 127）→ 之後全家
  （fork 繼承，v2.2 語意）自動同組。前台/後台一致（fate-sharing
  不分前後；每個 `run` 耗一個槽，見 §4 bounds）。
- state 文件加一欄：`"<pid> <start> <cg> <name>\n"`。
  讀取容錯舊格式（兩欄 → cg=0 = 無組殺器，走 v2.4 老路）。
- fork 失敗 / cgcreate 滿（`usize::MAX`）：直接報錯 exit 1，
  不留半吊子（槽位該漏就漏，見 §4；探測在 unshare 之前，
  順序：root → prog → cg → unshare → fork）。

## 2. `SYS_CGKILL = 53`（約 25 行，kernel 唯一新增）

- `cg_kill(cg) -> 已標記數`：cg==0 或越界（`>= s.cg.len()`）回 -1
  （root 組拒殺——殺全機不是 stop 該幹的）；否則收集
  「同組 + 非僵屍 + 非自己」逐個 `kill_with(-9)`（Blocked 的喚醒、
  踢 idle 全沿用；collect-then-act，不嵌套拿鎖）。
- 調用者自保：跳過 `current_pid`（ctr 在 root 組、私有組本來就不交疊，
  跳過是雙保險，自殺式 stop 直接變 no-op 而非全機陪葬，寫死）。
- 冪等：空組回 0（兼任「組空了沒」探針，見 §3）。
- 為何不用 pid 遍歷（user 側 `ps` 拼）：`ps_snapshot` 只見同 ns，
  跨 ns 點名只能問內核（v2.4 的 PIDINFO 同理；一事一 syscall）。

## 3. `ctr stop` 改按組殺（前台行為不變）

- 讀 state：活著 → `N = cgkill(cg)`（cg>0；legacy cg==0 走 v2.4 老路
  kill-pid1）→ poll 至「pid1 gone **且** `cgkill(cg)==0`」
  （10×1s；第二次起的 cgkill 純探針）→ 印
  `stopped <name> (killed <N>)` exit 0。
- 已 gone → `stopped <name> (already exited)`（冪等不變）。
- 超時 → `ctr: stop timeout` exit 1（init 罷工級別，理應不發生）。
- N 的確定性：suite 用 `linger`（見 §4），stop 時組內恒 2 活口
  （pid1 + 孫），故 `killed 2` 可斷言；kill-then-reap 競態不影響 N
  （N 在第一發 cgkill 即定格，收割只影響 poll 退出時機）。

## 4. `user/linger` + suite（確定性設計）

- `linger [secs]`（約 40 行，零輸出）：fork 一個睡子，
  自己也睡同樣久。與 `sleeper` 的唯一差別就是多那一次 fork——
  組內恒 2 活口，不依賴任何時序（子跑沒跑起來都在組裡，都算數）。
- suite（`life` 6 步，prog 換 `linger 30`，其餘不動）：
  `run -d` → `ps`（Up）→ `stop`（`stopped life (killed 2)`）→
  `ps`（`Exited (code -9)`）→ `rm`。test.sh +1 項（72+1=**73 項**）：
  `killed 2`。
- BOUNDS（寫死）：每 `run` 耗 1 個 cgroup 槽（256/boot 上限，
  push-only；回收需 pin 機制——v2.4 證明過 create/enter 分離下重用
  不 sound，故不做）。autorun 每 boot 約耗 8 個；交互每次 `run`
  耗 1 個；滿了 `cgcreate` 回 MAX → `ctr`  loud 報錯，不靜默。
  容器 proc 誤 `cgenter(0)` 可出金組（無 caps 模型，v2.6 不擋，寫死）。

## 5. 驗收

- `./test.sh` 全綠（73 項），零 `PANIC`/`FAIL`，連跑 2 輪。
- 手動：`run -d linger` 後 `ps` 見 Up；另開視角確認孫存在；
  `stop` 後整組消失（`killed 2`）；`rm -f` 不存在（本版不加，
  先停後刪紀律不變）。
- 舊測項零退化（重點：fg `run` 多一次 cgcreate/cgenter——
  root 組行為不變；`cgtest` 自建組 id 順延（autorun 跑它時已有
  life 組？不——autorun 順序上 cgtest 在 ctr suite 之前，
  id 不變；且斷言只認行為不認 id）。

## 6. 非目標（→ v2.7+）

- cgroup 槽回收/pinning、跨 cgroup 遷移已跑進程、`pivot_root`、
- `ctr rm -f`（stop+rm 一步到位，便利但非必要）、後台 stdio 重定向、
- CPU floor/share（CFS）、netns/veth、overlayfs、registry 認證、
  volume/bind mount、IO 權重、層級配額 enforced、cgroupfs、
  OOM-killer 啟發式。
