# muse-riscv-os v1.3（主線：virtio-net，第一個封包；只要 UDP）

## 0. 動機與範圍鐵律

内核至今無網路。本版只做「一張 virtio-net 卡 + 靜態 IPv4 + UDP 收發」，
證明端到端通路（guest↔host SLIRP）；**TCP 是獨立大版，不在本版出現**。

刻意排在鎖拆分之前：net 建在大鎖上，鎖交互只有「RX/TX 短臨界 + 沿用
exactly-once 的 `wake_net`」，比在分裂中的鎖架構上蓋新子系統便宜得多；
拆不拆鎖由 v1.4 按 v1.2 的 `contention` 數據判決。

## 1. 設計

### 1.1 驅動泛化（`kernel/src/fs/virtio.rs` 動刀，blk 行為不變）

- 現況是單設備寫死（`BASE 0x10001000`、單 queue、單 flight、`HDR/DATA/STB`
  全局）。改為 `VirtioMmio { base }` 結構：queue 裝配、submit、ISR 分發皆以
  `base` 參數化；blk 沿用 `VirtioMmio { base: 0x10001000 }` 包裝，行為零變。
- QEMU virt 的 MMIO 槽：`0x10000000 + n*0x1000`；blk 佔 `.1`，net 掛 `.2`
 （`0x10002000`）。開機按槽 probe，以 `DEVID` 區分（1=net，2=blk），
  找不到 net 印 `[NET] no device, SKIP` 繼續開機（`test.sh` 沒加網卡的老跑法不炸）。
- net 用 2 條 virtqueue（rx/tx；沿用 legacy-MMIO 單 queue 對程式碼，
  第二條照抄裝配）。TX 單 flight 沿用 blk 的 `DRV_BUSY` 模式（net 獨立一把）；
  RX 描述符常駐 + 完成 ISR 把包推進 `NET_RX` 環（短臨界，只拷貝）。

### 1.2 最小協議棧（新 `kernel/src/net/`，零外部依賴）

- 靜態配置：guest `10.0.2.15/24`，gw `10.0.2.2`，MAC 取設備 config。
  註明：這是 QEMU `-netdev user`（SLIRP）預設網段；換環境要改常數。
- 發包：UDP over IPv4 over Ethernet，IP/UDP checksum 手算；ARP 做完整
  （先 ARP 問 gw，學到 MAC 再發 UDP；30 行左右，不 hardcode SLIRP 的 MAC）。
- 收包：ISR 按 EtherType 分流（ARP 應答 → 學 MAC + 喚醒等待者；
  UDP 到本端口 → 進 socket 緩衝 + `wake_net`）。
- 新阻塞原因 `BLOCK_NET` + `task::wake_net()`（沿用 v1.x exactly-once 入隊；
  `kick_idle` 覆蓋，無需新 IPI 機制）。

### 1.3 Syscall（UDP 子集，3 個）

- `SYS_SOCKET = 37`：只接受 UDP（type 參數非 UDP 回 `-1`），回 fd
  （`fd_kind` 新值，用現有 16-fd 表）。
- `SYS_SENDTO = 38(fd, buf, len, ip_u32, port)`：ARP 未命中先阻塞等 MAC
  （有界超时回 `-1`，不 hangs 住 sh）。
- `SYS_RECVFROM = 39(fd, buf, len, timeout_ticks)`：無包則 `BLOCK_NET` 睡，
  超时回 `-2`（沿用 waitpid 的 WouldBlock 語意，用戶重試）。
- `user-lib` 加三個 wrapper；`close()` 沿用（fd_kind 清理）。

### 1.4 QEMU/測試線

- `run.sh`/`test.sh` QEMU 行加
  `-device virtio-net-device,netdev=n0 -netdev user,id=n0`。
- `tools/udp_echo.py`（host 端，50 行內）：監聽 `127.0.0.1:7777`，原樣回包；
  `test.sh` run1 前台啟動（background + pid 記住，跑完 kill；沿用 Ctrl-C
  管線 quirk 註記風格）。
- `user/udpping`：向 `10.0.2.2:7777` 發 8 位元組 magic，5s 內收到相同回包印
  `[TEST] net PASS` 否則 FAIL；sh autorun 加跑；`test.sh` run1 加斷言
  （55+1=**56 項**）。
- SLIRP 注意：首包外發會觸發 user-net 初始化，首包超時放寬到 5s（只放寬 net，
  不動既有時序斷言）。

## 2. 驗收

- `./test.sh` 全綠（56 項），零 `PANIC`/`FAIL`，連跑 2 輪；`net PASS` 穩定。
- 手動：進 shell 跑 `udpping` 多次皆 PASS；`blk` 回歸（驅動泛化沒弄壞磁碟：
  suite 全綠即證）。
- 無網卡起機（去 QEMU 參數）仍全綠除 net（`SKIP` 語意，斷言改止於 run1 報錯——
  預設 CI 環境一律帶網卡，此為手動保險）。

## 3. 非目標（→ v1.4/v1.5）

- TCP（重傳/窗口/擁塞是整整一版）、DHCP/DNS（靜態先行）、多 NIC/多 queue、
  效能（Gbps 級另說）、`ping`（ICMP 可作 v1.4 開胃菜）。

## 4. 實作血淚（v1.4 讀）

- **QEMU 自動掛載從最高槽往下填**：net 沒加 `bus=` 時落在 bus.7
 （`0x10008000`），不是想當然的 slot 2。解法是雙保險：cmdline 用
  `bus=virtio-mmio-bus.1` 釘住 + 內核按 DEVID 掃 16 槽（`info qtree` 是正解工具）。
- **空槽讀出來是 0，不是 fault**（至少 QEMU 10.2 如此）：guarded probe
  仍保留（跨版本保險），但當初的 early-hang 主因其實是別的時序問題——
  教訓：先懷疑自己的假設，用 `info qtree`/DTB 拿 ground truth。
- **BE 常數手寫必反**：`10.0.2.15` 是 `0x0A00020F` 不是 `0x0F02000A`；
  被 `ip 15.2.0.10` 骗了一輪。wire bytes 肉眼對一次再跑。
- **`contention` 讀數污染**（見 `v1.2.md`）：boot-markers 處歸零後仍 65–80%，
  主因是 `waitpid` 輪詢空轉。v1.4 判決用背靠背相對值；根治（`BLOCK_WAIT`）
  留 v1.5。
- **Loaded-host flake**：load>4 時 MTTCG 慢數倍，曾 120s 跑不完被誤判；
  run1 已放 180s。規則：同 spots 掛兩次才是真 bug，否則先看 `uptime`。
- **鎖拆分不在本版**：按 v1.4 判決行事，本版 net 程式碼只許用大鎖 + 短臨界，
  不許自創鎖序（免得判決後重審）。
