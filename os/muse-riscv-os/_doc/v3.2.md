# muse-riscv-os v3.2（主線： crates.io 管線——host 端打包）

## 0. 動機

v3.0/v3.1 的包都是 registry 啟動時用 echo ELF 現包的——能驗安裝器，
但證明不了「外部 crate 變成包」這條路。本版補 host 端管線：
任意 guest-target crate 目錄 → 交叉編譯 → ustar + manifest →
registry 上架。crates.io 在這裡只是一個「crate 目錄來源」
（免登入下載），guest 永遠碰不到它（plan3.x §0 判據）。

## 1. 語義

- `tools/pkgdemo/`：獨立 guest crate（自帶 `[workspace]` 脫離主
  workspace、`build.rs` 掛 `user-linker.ld`、path 依賴 `user-lib`），
  二進制 `fortune`：`fortune <args...>` 印 `fortune-sez <args...>`
 （一行，suite marker）。
- `tools/pkgbuild.py`：`pkgbuild --crate <dir> --pkg <name>
  --version <ver> --bin <bin> --out <dir>`：
  1. `cargo build --release --target riscv64gc-unknown-none-elf`
     （cwd=crate 目錄；沿用 root toolchain + `.cargo` target-feature）。
  2. 讀 `target/.../release/<bin>` ELF + `--add <arc>=<hostfile>`
     額外檔案 → ustar（`bin/<bin>` + 附檔；guest untar 只認
     regular/dir，`build_pkg_bin` 同款約束）。
  3. 寫 `manifest`（`name:`/`version:`/layer 行；`--depends` 可選）。
  失敗 loud（cargo 非零、ELF 缺失、檔案缺失任一即非零退出）。
- `--src crates <name> <ver>`（可選驗證）：從
  `static.crates.io/crates/<name>/<ver>.download` 抓 `.crate`
  解包成 crate 目錄（stdlib `urllib`+`tarfile`，免登入）。
  生態現實：今天 crates.io 上沒有可跑的 guest crate（要有也得
  先依賴已發布的 `user-lib`）——本版只驗證「抓得下來、解得開」，
  端到端 crates.io→guest 等第一個 guest crate 出現（v3.9 已兌現，
  見 `v3.9.md`）。
- registry（`img_registry.py`）：啟動時 `import pkgbuild` 現場編
  `pkgdemo` → `/pkg/fortune/{manifest,fortune.tar}` 路由。
  編譯失敗 → 該路由 404 + stderr loud（suite 大聲失敗，不靜默）。
  test.sh 流程不動（registry 啟動本來就要求 cargo 建樹已就緒，
  讀 `ECHO_ELF` 同款假設）。
- `user-lib` 發布就緒：補 `description`/`license`/文件註解、
  `cargo package --list` 能過。**不執行 `cargo publish`**
  （要帳號 token；等主人回來決定）。

## 2. suite（確定性設計：管線產物可裝可跑）

```
ctr install 10.0.2.2 8091 fortune   → pkg-installed fortune 1.0
ctr list                              → PKGLS fortune 1.0
fortune hello-from-fortune            → fortune-sez hello-from-fortune
ctr remove fortune                    → pkg-removed fortune
```

- test.sh +4 項（run1）：上列四個 marker。
- 手動：`pkgbuild --src crates itoa 1.0.15 --out /tmp/x`
  （抓包驗證，不進 suite——第三方版本會漂）。

## 3. 非目標（→ 將來）

`cargo publish user-lib`（等帳號）、registry 磁碟包目錄、
`upgrade`、包簽名、guest 側編譯器（永不）。
