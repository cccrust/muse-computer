# muse-riscv-os v1.6（主線：journal 保 crash 一致性；配菜 ping）

## 0. 動機

reclaim、net、TCP 之後，系統能長期跑、能對外服務——唯獨 crash 會靜默
毀 FS（dirty 掛載只有 fsck-lite 重建 bitmap，寫一半的內容自生自滅）。
本版補上最後一塊正確性拼圖：全數據 journal（metadata + data），斷電
重放，torn page 不可能。

## 1. 設計（新 `kernel/src/fs/jnl.rs`，`disk.rs` 只動三處）

### 1.1 為何是全數據 journal 而非 metadata-only

- metadata-only 保不了覆寫的原子性（舊內容/data 寫一半照樣 torn）。
- 4MB 磁碟、write-through 路徑：2× 寫放大無感，換完整原子性。正確優先。

### 1.2 格式（磁碟尾部固定環，`mkfs` 保留）

- 位置：最後 512 sectors（`[nblocks-512, nblocks)`），superblock 加欄位
  `journal_lba@52`、`journal_blocks@56`（48=dirty 沿用；欄位全零=無 journal，
  老 image 優雅降級）。
- 槽位 2 sectors：A=`{magic JRNa, gen u32, seq u32, lba u32, crc u32}`、
  B=512B 數據。Header 1 sector：`{magic JRN1, gen u32, commit u32}`。
- 環大小 256 條記錄；`balloc`/`free_blocks`/`rebuild_bitmap` 跳過 journal 區。

### 1.3 寫協議（同步 write-through，無 batching）

- `blk::write(lba, data)` 內：取 `JLOG` 鎖 → `seq=next++` → raw 寫 A、B →
  raw 寫 header(`commit=seq`) → 解鎖 → 照常 home 寫（cache+device）。
  journal 自身走 raw `virtio::write_block`（不經 cache、不遞迴）。
- crash 切面（全部正確）：
  - A/B 寫一半 → crc/magic 壞 → replay 跳過（home 是舊版；write 未 ack ✓）。
  - B 完、commit 前 → `seq > commit` → 跳過（同上 ✓）。
  - commit 後、home 前 → replay 補上（已 ack 的寫必活 ✓）。
  - home 後 → replay 冪等（同 lba 同內容 ✓）。
- 重放只認 `gen == header.gen && seq <= commit && crc ok`，按 seq 順序 raw
  寫回。併發正確：seq 分配在鎖內，跨核交錯的記錄各自完整，重放冪等故
  順序無礙。循環覆寫安全：被覆寫的記錄其 home 早已同步落盤（write-through
  保證）。
- dirty 掛載：先 replay（印 `[FS] journal replayed N`），再沿用
  rebuild_bitmap（冪等）。
- 乾淨關機（既有 `SYS_SHUTDOWN` 路徑）：`gen++`（舊記錄一筆作廢，免清盤）
  → `set_dirty(false)`（順序反了也安全：dirty+新gen=無可replay ✓）。

### 1.4 改動面

- `jnl.rs` 新檔：格式常數、crc（沿用 `ip_cksum` 模式另寫 `jnl_crc`）、
  `record()`、`replay()`（`#[cfg(test)]` 單元測試：編解碼+torn 跳過+冪等）。
- `blk.rs`：`write()` 內調 `jnl::record()`（journal 關閉時零開銷一分支）。
- `disk.rs`：mount 內 dirty→`jnl::replay()`；superblock 讀 journal 欄位；
  balloc 系跳過 journal 區；其餘**一字不動**（攔截點以下全透明）。
- `mkfs`：superblock 寫 journal 欄位 + 尾部清零；`ramfs` fallback 不變
  （無 journal，印一行說明）。

## 2. 斷電測試（test.sh 新 §11，殺真的 `kill -9`）

- 新 `user/crashwrite`：`write` 模式循環覆寫 `/CRASHDAT`（N 個 4K 頁，
  每頁 `[ver:u32][idx:u32][fill]` 全頁一致）；`check` 模式逐頁驗證
  （全零未碰，或某一完整版本——torn 即 FAIL），印 `[TEST] crash PASS/FAIL`。
- stage 11（全 suite 最後，image 狀態無後顧）：bootA 背景跑
  `crashwrite write` → host `sleep X; kill -9 $QEMU_PID`（真斷電，無關機
  流程）→ bootB（同 image，不重建）跑 `crashwrite check` → 斷言
  `journal replayed` + `crash PASS` + 無 PANIC。kill 點隨機但性質恆成立
  （torn 與否跟時機無關），故斷言確定。
- host-tests 加 jnl 單元測試（`cargo test` 即跑）。

## 3. 配菜 ping（ICMP echo，1–2 天量級）

- `socket(2)` = ICMP：`connect(ip)` 存 peer；`send` 發 echo request
  （id=lport，seq 自增）；`recv` 收匹配的 echo reply（payload 去頭）。
  入境 echo request 順手回覆（正確性，SLIRP 轉不轉發是另一回事）。
- checksum 標準實現；RX 分流 IP proto 1；`BLOCK_NET`/`wake_net` 沿用。
- `user/ping`：`ping 10.0.2.2` 發 4 包、等回（ticks 計 RTT），印
  `[TEST] ping PASS/FAIL`；sh autorun 加跑（無需 server，處處可跑）；
  test.sh +1 項（57+2=**59 項**：crash、ping）。

## 4. 驗收

- `./test.sh` 全綠（59 項），零 `PANIC`/`FAIL`，連跑 2 輪。
- `journal replayed` 在 §11 穩定出現（實測 254–255 條，環幾乎寫滿）；
  `crash PASS` 穩定；`ping PASS` 穩定。
- 手動：`kill -9` 任意時機 + 重啟，FS 可用、舊測項不退化。

## 5. 非目標（→ v1.7+）

- journal batching/group-commit（效能，磁碟小無感）、metadata-only 模式、
 fsck 全掃描（坏 inode 修復）、TRIM、swap、TCP 主動端（v1.7 候選）。

## 6. 實作血淚（v1.7 讀）

- **dirty flag 必須 mount 設、halt 清**：只有後者時，kill -9 後掛載是
  「乾淨」的，重放永遠跑不到、測試空轉通過。先修協議再談測試有效。
- **LIFO free list 無合并必碎**：syscall 級 Strings/Vecs churn 下，
  8MB 堆在完整 autorun + writer soak 後連 32KB 都配不出（total 尚足）。
  dealloc 順手排序插入+合併鄰居（~25 行）；halt 印 `[MM] heap free/largest`
  當水位（實測 7.6M/7.1M）。
- **測 SUT 內常駐行程要用 prompt 門控 stdin**：autorun 的 console reader
  會啃掉 early input（`crashwrite` 變 `ashwrite`）；`for...grep '^sh\$ '`
  等 prompt 再送（run4 同理）。
- **kill -9 測完記得 `pkill` 殘留**：佔著 8080 的 QEMU 會讓下一輪 hostfwd
  起不來，報錯長得像 guest 的問題。
- **原子性以 journal 單位為準**：全數據 journal 保的是 512B sector，
  4K 頁寫測試註定 torn——測什麼粒度，先想清楚保證是什麼粒度。
