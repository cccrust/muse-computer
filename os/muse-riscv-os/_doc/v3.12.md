# muse-riscv-os v3.12（併發安裝 /tmp 競態修復）

## 0. 動機

`install` / `upgrade` / `pull` 共用固定 scratch 檔名（`/tmp/manifest`、
`/tmp/p0.tar`、`/tmp/pindex`、`/tmp/l0.tar`）。兩個 `ctr` 同時跑
（一個 background、一個 foreground，shell 完全允許）就會互相覆寫：
讀到寫一半的 manifest → 裝錯版本或直接炸。單線跑永遠碰不到，
所以 suite 從沒抓到過——手動併發探針實證必現。

## 1. 語義

- 新增 `tmp_path()` helper（`user/ctr/src/main.rs`），按 pid 後綴：
  manifest → `/tmp/manifest.<pid>`，index → `/tmp/pindex.<pid>`，
  包 layer → `/tmp/p<idx>.<pid>.tar`，pull layer → `/tmp/l<idx>.<pid>.tar`。
  NUL-terminated；內容恆小於 64B（最長形狀 5 + 8 + 1 + 20 + 4；
  pid 在單次 boot 內不重用——v2.4 保證，計數只到 test-hundreds）。
- 所有調用點切過去，無一殘留固定名：`cmd_pull`（manifest + layers）、
  `fetch_index`、`install_one`（manifest）、`verify_tars`、
  `install_layers`（下載/解包/掃描三處 + manifest unlink）、
  `fetch_layer`、`upgrade_one`（manifest + 解包/掃描 + unlink）。
  遞迴 install 的父子幀共用同一 pid 命名（父等子返回才繼續，無交錯）；
  fork 出去的 wget 走 argv 拿路徑（自己不重建）。
- 單線行為逐位元不變：同進程重建同名，O_TRUNC 語義照舊。

## 2. suite（確定性設計：本版無新 marker）

- 行為單線不變，故 suite 不加斷言（119 項維持）。
- 證明用手動併發探針（可重現步驟）： полном stubs 開機 → prompt 後
  `ctr install 10.0.2.2 8091 farewell &`，3 秒後
  `ctr install 10.0.2.2 8091 fortune` 前台跟進 → 兩邊 fetch 在時間上
  交錯 → 三包全裝上、`list` 版本全對、刪乾淨、clean halt、零 PANIC。
  舊代碼此場景必定互踩（同一 `/tmp/manifest` + `/tmp/p0.tar`）。

## 3. 非目標

- 掉電/被殺中途的原子性（#2 問題：撕裂 store + db 不一致，
  要先定 staging 重放還是加 `SYS_RENAME` 再動）。
- 併發 `db` 追加交錯：O_APPEND 短寫實務原子，未形式化驗證；
  行級完整（兩行都在、順序不定），可接受。
- 陳舊 tmp 殘留：kill -9 會留下 pid 檔（KB 級，/tmp 語義本就如此）。
