# muse-riscv-os v2.0（主線：容器地基——chroot 文件系統隔離）

## 0. 動機

Docker 四層（fs 隔離 → pid 名字空間 → cgroup 限額 → net/mount 豪裝）
必須按序做。本版只做第一層：進程自己的 root 視圖 + 越獄不可能 +
組裝工具 + 自測。pid/限額/網路是 v2.1+ 的事，這裡不碰調度不碰協議。

## 1. 設計（`task/mod.rs` 路徑層 + 一個 syscall）

### 1.1 per-proc root（`Proc.fsroot[128]` + `fsroot_len`，注意 `root: usize`
是頁表根，名字錯開）

- 預設 `/`（init；舊語意逐位元相容）。
- `fork` 繼承（`clone_proc_info` 加兩欄）；`spawn` 置 `/`。
- `getcwd` 回傳容器視圖（chroot 後就是 `/`，Unix 語意）。

### 1.2 雙錨點解析（核心正確性，只此一處）

- `resolve_path(root, cwd, path)`：絕對路徑錨定 root（`/bin/sh` →
  `<root>/bin/sh`），相對路徑錨定 cwd；`..` 遇到 root 邊界即停
  （stack 長度不短於 root 分量數）。**containment by construction，
  不是事後檢查**——呼叫方不可能繞過。
- `resolve_for(pid, path)` 改走雙錨點；全 syscall（open/read/write/
  mkdir/link/unlink/exec/getdents/chdir…）經它自動被囚，無需逐個改。
- `set_cwd` 維持（chdir 先 resolve 已夾緊）；`get_root`/`set_root` 新增。

### 1.3 `SYS_CHROOT = 45`（只收緊，不放寬）

- 語意：`set_root(pid, resolve_for(pid, path))`，目標須存在且是目錄
  （`disk::is_dir` 新增；否則 `-1`），成功回 0。
- 收緊性免費得來：解析用的本來就是舊 root，解出來的一定是子孫——
  不需要額外的前綴檢查（前綴檢查是經典 bug 溫床，字串比較繞得過）。
- 已知限制（誠實寫在這，不修）：chroot 前已開啟的 fd 仍指向外界
  （Unix chroot 同款限制）；`..` 在 root 停住但 `getcwd` 不洩露真實前綴；
  pid/網路/資源視圖本版一律不隔離（v2.1+）。

## 2. `user/ctr`（組裝工具，零拷貝）

- `ctr <name>`：`mkdir /ctr`、`mkdir /ctr/<name>/bin`，`getdents /bin`
  枚举後逐個 `link` 進去（hardlink，不拷貝；可執行位隨 inode 走）。
  印 `ready /ctr/<name>`。冪等（重跑不炸：存在即跳過）。
- 為何不用 cp：FS 尚無 cp 工具是一回事，更重要的是 link 讓容器 rootfs
  幾乎零成本——這正是 chroot+hardlink 這條老路的精髓。

## 3. `user/chroot_test`（自測，不依賴 stdin 時序）

- 建 `/ctrtest` + link 兩個二進制 → `chroot("/ctrtest")` →
  斷言 `getcwd()=="/"`、`open("/bin/sh")` 成功、`open("/TESTDATA")` 失敗
  （外界）、`open("/../bin/sh")` 失敗（`..` 越獄）、`chroot("/nope")` 回 -1 →
  `[TEST] chroot PASS/FAIL`。全走返回值斷言，無時序。
- sh autorun `run_one` 跑它；test.sh +1 項（60+1=**61 項**）。

## 4. 驗收

- `./test.sh` 全綠（61 項），零 `PANIC`/`FAIL`，連跑 2 輪。
- 手動：`ctr demo` → chroot 進去（手動 `chroot` 指令？本版不加 shell
  builtin，`ctr` 只組裝；交互驗證用測項覆蓋，需要 builtin 是 v2.1 議題）。
- 舊測項零退化（重點：`resolve_path` 簽名變了，所有調用點重審；
  root=`/` 時行為逐位元同舊）。

## 6. 實作血淚（v2.1 讀）

- **chdir 存的一定是容器視圖**：`resolve_for` 回的是 host 全路徑，
  直接 `set_cwd` 會洩露真實前綴 + 下次解析雙重套 root。剥離寫在
  `sys_chdir`（`strip_prefix`，`/` 特例合併處理）。
- **共享頁要 UNION 語意**：`protect()` 保持 OR-only，exact-set 另開函數
  （這是 v1.9  stash 的教訓，本版沒重蹈）。
- **stdin 測試一律 prompt 門控**：autorun 期 console reader 會啃 early
  input（`crashwrite`→`ashwrite` 前例）；run3/run4/§11 一律
  `poll '^sh\$ ' 再送。`respawn` 斷言只在 Ctrl-C 打中 prompt 的 sh 才成立。
- **respawn 跳過 autorun**（`--quick`）：否則 run3 的 halt 要等第二遍
  autorun（且第二遍的輸入會被吃掉）。init 首胎完整、重生快速。
- **stale-current + kill-check 自激迴圈**：`switch_to(None)` 不清 current，
  下一個 tick 的 kill-check（跑在 schedule 之前）對著僵屍反覆 `do_exit`，
  永遠到不了 vacate。修：kill-check 加 `is_running` 門 + idle 兩處 vacate；
  另加 REEXIT/DUP-SWITCH 探測（本輪零觸發）+ KERNEL-TRAP 探測
  （注意：idle wfi 的合法中斷 sepc 落在 idle 區，要豁免，否則全機自殺）。
- **慢 host 判定流程**（本版三次誤報學到的）：先看 death 點是否推進
  （推進=慢，定點=死）、單核對照（smp1 全速過即排除內核死鎖）、
  v1.8 worktree A/B（同負載同綠即環境）。MTTCG 在 load>5 會 convoy 崩塌，
  suite 的 poll/timeout 預算只增不減，爛規則是「同點掛兩次才是真 bug」。
