# muse-riscv-os v3.3（主線：升級鏈——index + `upgrade` + `autoremove`）

## 0. 動機

v3.0–v3.2 只會裝不會升（`already installed` 一擋了事）。
本版補：多版本 registry、版本比較與範圍、升級、孤兒清理。

## 1. 語義

```
ctr install <host> <port> <pkg>[=ver]   # 無約束 = 最新版；=ver =釘選
ctr upgrade <host> <port> [<pkg>]       # 無參數 = 全升
ctr autoremove
```

- 版本：三段式 `x.y.z` 數字比較（不合規 → loud 拒收）。
  依賴 token：`name`、`name=ver`（沿用）、`name>=ver`（新增；
  `>`/`<`/`~` 不做）。
- registry：`/pkg/<name>/<ver>/manifest` + layer（啟動現包，
  與 v3.0 同招——**不落磁碟**，plan 階段的 `tools/packages/`
  想法已斃：blob 進版控 + 重打包流程，收益為負；見 plan3.x §5），
  另加 `/pkg/<name>/index`（版本列表，一行一版 + `#` 註解）。
  舊無版號路由（`/pkg/<name>/manifest`）**刪除**（v3.0 suite 改
  `hello=1.0`，marker 不動——釘選語法的第一次實證）。
- `install`：有約束 → 直接取該版 manifest；無約束 → 先抓 index
  取最大版。依賴 DFS 照舊（約束透傳）。
- `upgrade`：db 版本 → index 最大版；相同 → `already latest`
  exit 0（冪等，suite 可重跑）；更新 →「先裝後刪」
  （雙 store 並存中間態，失敗留舊版；db 永遠指完整版），
  印 `pkg-upgraded <name> <newver>`。新版依賴重解（裝新依賴；
  舊獨佔依賴變孤兒，`autoremove` 收）。
  **已知缺口**：upgrade 不重驗依賴者的 pin（如 farewell 要
  `hello=1.0` 而 hello 被升到 2.0）—— headings 式拒絕以後再說，
  寫死在這。
- `autoremove`：db 裡「不在任何已裝包 depends 閉包裡」的包，
  不動點循環刪。每刪一個印 `autoremove <name>`（沿用 remove
  內核，marker 不同）。無孤兒 → 靜默 exit 0。
- 非目標：downgrade（`install =舊版` 算降級？可以，install 本來
  就能裝指定版——upgrade 永遠只往最新走）、並行下載、delta。

## 2. suite（確定性設計：釘選+升級+孤兒）

registry 加 `hello 2.0`（同 echo ELF，`hello.txt` 改
`pkg-hello-txt-v2`）。autorun（fortune 段後）：

```
ctr install 10.0.2.2 8091 hello=1.0   → pkg-installed hello 1.0
ctr upgrade 10.0.2.2 8091 hello       → pkg-upgraded hello 2.0
cat /pkg/hello/hello.txt              → pkg-hello-txt-v2
ctr list                              → PKGLS hello 2.0
ctr install 10.0.2.2 8091 farewell   → （hello 已是 2.0，dep 要 =1.0 → version mismatch！）
```

慢著——上面最後一行會炸：farewell 的 dep 是 `hello=1.0`，
db 裡是 2.0 → mismatch exit 1。這正好是依賴約束的**負向實證**，
但會把 suite 的 farewell 鏈（v3.1 段在前，已跑完，不影響）
和這裡的流程攪在一起。抉擇：把 `version mismatch` 負向測在這裡
收了（marker 現成），farewell 段保持 v3.1 原樣（它跑在 db 乾淨時）。
本段結尾 `ctr remove hello` 收乾淨（2.0 的 store）。

```
ctr install ... farewell              → ctr: version mismatch (hello)
ctr remove hello                      → pkg-removed hello
ctr autoremove                        → （無孤兒，靜默；不斷言）
```

autoremove 正向：`install farewell`（v3.1 段尾 db 又乾淨了……
不對，v3.1 段把 farewell+hello 都刪了）。autoremove 正向實證
要一個孤兒：`install farewell` → `remove farewell`
（hello 留下變孤兒）→ `autoremove` → `autoremove hello`。
放在 v3.1 段**之後**另起一段（v3.1 段一字不動）：

```
ctr install 10.0.2.2 8091 farewell   → pkg-installed farewell 1.0
ctr remove farewell                  → pkg-removed farewell
ctr autoremove                       → autoremove hello
ctr list                             → （只有表頭；不斷言，用 PKGLS 行缺席反證？不斷言）
```

- test.sh +6 項（run1）：`pkg-upgraded hello 2.0`、
  `pkg-hello-txt-v2`、`PKGLS hello 2.0`、`version mismatch`、
  `autoremove hello`，外加 v3.0 段改 `hello=1.0`（marker 不變）。
  `already latest` 走手動（重跑 upgrade）。
- 手動：`upgrade` 無參全升、`install hello=9.9`（404→fetch 失敗）、
  `depends: hello>=1.0`（registry 暫無此包，手動改樁驗，不進 suite）。
