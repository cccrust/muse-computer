# muse-riscv-os v3.16（主線：偶發全凍結的根因追查——未完）

## 0. 現象（QEMU monitor 實證，非推測）

- 凍結時 3 hart 卡 `SpinMutex<Sched>::lock_counted` 自旋，
  第 4 hart 卡 `__trap_entry` 起點：pc=sepc=stvec=`__trap_entry`、
  scause=12（instruction page fault）、stval=同地址。
- `SCHED.locked`=1 且 per-hart 臨界區計數全非零：鎖確實有人拿著，
  但沒有 hart 在臨界區內推進。
- 手動 walk 當前 satp（0x813d8-root）：root 表全零——trap 向量所在頁
  在該表無映射，每次 trap 重 fault，無限迴歸；log 凍結、無 PANIC。
- 觸發：只見於 used-image boots（fresh 12+ 全過）+ host 高負載；
  同一 image 重開 outcome 不同（race/timing，非確定性 state）。

## 1. 已排除

- SIE 中斷紀律：實作過 xv6 式 push_off/pop_off（只接 `sched_lock`
  choke 點），凍結依舊、徵兆不變，已 revert。timer-ISR 重入自死鎖
  不是本次凍結的機制（SIE mask 下 synchronous fault 照樣能拿著鎖
  進 regress）。
- 磁碟壓力：凍結 image 59% used；fsck/journal 正常。
- stub 存活：stub 全死時 autorun 反而飛快（RST 快速失敗）；半殘 stub
  的 retry-burn 看似凍結但 log 仍在推進，真凍結是零推進。
- v3.15 嫌疑：installs 段在凍結點之後；socket 耗盡修復與此無關；
  v3.14 二進位亦有同徵兆（r2 qemu4/qemu7）。
