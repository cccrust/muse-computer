# muse-riscv-os v2.2（主線：cgroup-lite——記賬 + 內存 cap，容器第三層）

## 0. 動機

v2.0/v2.1 給了容器邊界（root 視圖 + pid 視圖），但沒有配額：一個
`while(1) sbrk()` 能吃光 128MB 拖全機陪葬（`expect("oom")` panic）。
本版補上最要緊的一種隔離——內存記賬與上限。CPU 份額、IO 權重是 v2.3+
議題；無用戶體系，權限檢查從簡（全員 root 語意，寫死在這）。

## 1. 設計

### 1.1 記賬（frame.rs 內，不新增鎖）

- `owner[32768]u16`（frame→cgid，全 RAM `[0x80000000,0x88000000)` 下標，
  64KB 靜態）+ `CG_USE[256]u64` + `CG_LIM[256]u64`（0=不限），**全在既有
  `ALLOC` 鎖下**。用量/limit 鏡像放 frame 側是故意的：`alloc` 熱路徑只拿
  一把鎖，絕無 sched↔frame 逆序。
- 歸屬判定（alloc 時）：調度器活躍 **且** current 有效 → current 的 cgroup；
  否則（boot/idle 上下文）記 cgroup 0（root，不限）。fork 為子配的幀記到
  父 cgroup——子繼承同一 cgroup，自動正確，無需特判。
- `dealloc_frame(pa)` 查表扣賬（單一 choke 點；`free_user_space`、
  munmap 全經此處 ✓）。

### 1.2 cgroup 元數據（task 側，Sched 鎖下）

- `Cg { parent: usize }`，`Sched.cg: Vec<Cg>`，0 號預建（root）。
  parent 只記錄不遍歷（層級執行是 v2.3+ 的事；v2.2 是扁平執行+層級記賬）。
- `Proc.cg: usize`（fork 繼承；spawn 置 0）。
- API（三個 syscall，够用即止）：
  - `SYS_CGCREATE = 47(limit_frames) -> cgid`：建子 cgroup 並設上限
    （一步到位，省掉 create+limit 兩次往返；limit 同步寫 frame 側鏡像）。
    父是調用者所在 cgroup。
  - `SYS_CGENTER = 48(cgid)`：自己搬家（存在性檢查；跨樹不擋，無用戶體系）。
  - （查詢走 `SYS_MEMSTAT` 的延伸？不——用量由 cgtest 側面驗證，
    詳見 §2；`halt` 行加 `[CG] n=<組數>` 存在性即可。限額讀回以後再說。）
- `user-lib`: `cgcreate(limit)`, `cgenter(id)`。

### 1.3 上限執行（`alloc_frame` 內，超限回 None）

- 記賬 cgroup `use >= lim > 0` → 本次分配回 `None`（不 panic）。
- `expect("oom…")` 審計（逐個改，用戶可達路徑一律優雅失敗）：
  - `sys_sbrk` 增長、`sys_mmap` → 回 `-1`（`alloc_map_user`/`map_user`
    加 bool 回傳，調用點跟著改：spawn/exec 中止回 false，sbrk/mmap 回 -1）。
  - `fork`（new_proc/clone 路徑）→ 回 `usize::MAX`（用戶側 `<0` 即失敗，
    現有 `>0/==0/else` 三分支天然相容）。
  - `exec` → 已有 false 通道 ✓ 順延。
  - boot 期/內核表路徑保留 `expect`（root cgroup 不限，觸發即真 OOM，
    panic 正確）。
- 物理 OOM（整機無幀）語意不變：`None` 層層上傳，走到哪算哪（最終是
  syscall `-1`，不是 panic——v1.x 的 panic-on-OOM 至此退役於用戶路徑）。

## 2. `user/cgtest`（自測：超限的是它，死的不能是全機）

- 父：基線 `memstat` → `cgcreate(1000)` → `fork` → 子 `cgenter(id)` 後
  `sbrk` 循環到 `-1`（必須拿到 -1 而不是全機 panic）→ `exit(0)`；
  父 `waitpid` 收 code 0 → 自己再 `sbrk(1MB)` 必須成功（兄弟不受影響）→
  尾基線 `memstat` 差值小閾值（回收仍工作，v1.2 語意延續）。
- 任一步走樣（panic/超時/父被牽連）即 FAIL。全返回值斷言，無時序。
- sh autorun `run_one` 跑它；test.sh +1 項（62+1=**63 項**）。

## 3. 驗收

- `./test.sh` 全綠（63 項），零 `PANIC`/`FAIL`，連跑 2 輪。
- `cgtest PASS` 穩定；舊測項零退化（重點：root cgroup 不限，
  不設 cap 的世界行為逐位元同舊）。
- 手動：`cgcreate` 小配額 +  hog，宿主照跑（演示用，不進斷言）。

## 4. 非目標（→ v2.3+）

- CPU 份額/權重、IO 限速、層級配額 enforced（記賬結構先留 parent）、
  跨 cgroup 遷移已跑進程的複雜語意（只許自己搬家）、users/capabilities
  驅動的權限檢查、cgroupfs 偽文件系統、OOM-killer 啟發式（超限回 None
  即是本版的全部「策略」）。
