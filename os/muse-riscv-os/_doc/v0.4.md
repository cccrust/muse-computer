# muse-riscv-os v0.4（已實作，`test.sh` 23 項全過）

主線：**中斷驅動 I/O**——UART RX 中斷 + 真正 blocking read + timer 喚醒 + Ctrl-C/EOF。virtio-blk 維持 polling（可靠，留待後續）。核心 trap、排程、測試框架小幅擴充；on-disk 格式不動。

## 1. PLIC 接線（`kernel/src/plic.rs` 新增）

- QEMU virt：UART0 IRQ=10，PLIC base `0x0c000000`。context1（hart0 S-mode）：enable `0x2080`、threshold `0x201000`、claim `0x201004`，priority 逐項 `0x4*irq`。
- `plic::init()`：priority[10]=1、enable bit10、threshold=0。MMIO 區段 `0x0c000000..0x0c300000` 需補進 kernel page table（現只映射 UART+virtio）。
- 啟用順序：PLIC 設定 → `sie` 置 STIE（已有）+ SEIE（bit9）→ `stvec` 不動。kernel 內仍 `SIE=0`（中斷只在 U-mode 進 trap，不處理巢狀）。

## 2. UART RX 中斷 + 輸入 ring（`uart.rs` 擴充）

- IER（offset 1）bit0 置 1（received-data-available 中斷）；ISR 把 RBR（offset 0）讀乾（LSR bit0 判空）推進 256B ring（`.bss` + SpinMutex）。
- `getchar()` 先排 ring 空再讀 RBR（polling 路徑保留，早期開機印字用）。
- Ctrl-C（`0x03`）：不進 ring，轉 `kill(fg)`（見 4），exit code 130；Ctrl-D（`0x04`）：推 EOF 標記，`read` 把已到位元組先回、下次回 0。

## 3. 真正 blocking（`task` + `syscall`）

- `Proc` 加 `state::Blocked` + `blocked_on`（0/1=stdin/2=sleep）+ `wake_at: u64`。queue 不變量維持「等待者不在 queue」：block 的任務自己設 Blocked + yield，`schedule_point` 不重排；wake 方（ISR/timer）才 `Runnable + push_back`。
- `sys_read(stdin)`：ring 空 → `Blocked(stdin)` + yield（不再回 0 忙等）；`sys_sleep(n)`：`Blocked(sleep, ticks+n)` + yield——順手修掉舊 `sleep_ticks` 在 kernel 內空轉等 tick（SIE=0 永遠等不到）的潛在死鎖。
- timer tick（trap 內）：掃 `Blocked(sleep)` 且到期的 wake。UART ISR：wake 全部 `Blocked(stdin)`。
- `kill()` 加喚醒：被 kill 且在 Blocked 的任務轉 Runnable，讓它下次 trap 入口檢查到 flag 即 `exit(-9/-3)`（見 4）。

## 4. 前景與 Ctrl-C（`setfg` syscall）

- 新增 `SYS_SETFG=24`：`sh` 在前景等待前 `setfg(child)`、回來後 `setfg(self)`；prompt 阻塞時 fg=self。
- UART ISR 見 `0x03`：若 `fg_pid != 0` 則 `kill(fg)`（exit code 130，仿 128+SIGINT），kernel 印 `[PROC] pid=N killed`；`sh`（init 子行程）被殺 → init 重生 sh（現有 respawn 路徑）。
- `jobs`/`bg` 不受影響（只殺 fg）。

## 5. user 層

- `user-lib`：`setfg(pid)`；`sleep` 已有。
- `sh`：前景等待前後 setfg；`jobs`/`halt` 不變；autorun 加 `sleep(5)` 自測印 `[TEST] sleep PASS`（免新 crate）。
- 其餘 app 不動（`read_line` 的 0-回傳重試迴圈在 blocking 語意下自然收斂：EOF 回 0 即跳出）。

## 6. 驗收（`test.sh` 加 run3，不動 run1/run2）

- run3 "interactive"：stdin 用 `(sleep 18; printf '\x03'; sleep 2; printf 'halt\n')` 管線（非 `/dev/null`；pipe 在此 QEMU 版本無靜默問題，tty 才有），同一 `fs.img`。
- 斷言：`killed` + `respawn`（Ctrl-C 殺掉 prompt 的 sh，init 重生）+ `halting`（重生 sh 吃到 halt 正常關機）+ 無 PANIC。25s 窗口不變（halt 會提早結束）。
- run1/run2 維持 `< /dev/null`（stdin EOF 語意：prompt 的 read 回 0 即讓出，不耗 CPU）。

## 7. 非目標

- virtio 完成中斷（維持 polling）、MSI-X、多 hart（PLIC context 只配 hart0）、完整 job control（`fg` 內建、SIGSTOP）、UART TX 中斷。

## 8. 實作結算（與規劃的差異）

- kill 檢查放 trap 入口（全部 trap 類型），而非只 ecall 分支——timer tick 也能處決，woken 任務（prompt 的 sh）最多再跑一個 tick 即死，無需改 `schedule_point`。
- `echo` 無參數路徑改不碰 stdin：usertests 跑 `echo`（argc=0）時 stdin 阻塞會餓死整條 autorun；互動式裸 `echo` 印預設句（旧 stdin 回顯行為捨棄，`echo text` 與 `echo < file` 不受影響）。
- 改 user app 必重跑 `mkfs`（映像檔內嵌舊 ELF）：`echo` 改完第一次開機 hang 就是這坑。
- `test.sh` run3 用管線 stdin（pipe 無靜默問題，只有 tty 有），Ctrl-C 送 `\003`（bash 3.2 `printf` 不認 `\x03`）。
- `sleep(5)` 50ms；`timer::sleep_ticks` 舊函式留置未刪（dead code warning 而已）。
