# muse-riscv-os v0.3（已實作，`test.sh` 18 項全過）

延續 v0.2：磁碟 FS 與 virtio 已穩，主線轉向「更像 Unix 的行程與檔案語意」。核心、排程、測試框架都不動；on-disk 格式小幅擴充（向後相容讀取舊映像檔，見 4）。

## 1. 主線：exec 參數（argv）

現況 `exec(path, argv)` 直接忽略 argv，`cat` 只能讀固定 `/README`、`echo`/`grep` 只能讀 stdin——shell 形同半套。

- Loader（`task::exec` / `spawn_from_elf`）：在 user stack 頂端由高往低布置 `[strings][argv 指標陣列][argc]`，`sp` 指 argc，沿用 Unix 慣例（riscv64 LP64：argv 為 u64 陣列 + NULL 結尾，16B 對齊）。
- `user-lib`：各 app 的 `_start` 改從 `sp` 取 argc/argv 傳給 `main(argc, argv)`（9+1 個 app 逐個改 Entry 樣板，邏輯不動；先改 `cat`/`echo`/`grep` 吃參數，其餘忽略參數照舊）。
- shell：`exec_cmd` 切 token（支援引號先不做，只切空白），`exec_simple`/pipe 子行程把 argv 陣列傳進 `exec`；`cat /OUT`、`echo hi > /f`、`grep pat < /f` 因此可用。
- 驗收：`test.sh` 加 `cat ARG PASS`（`sh` 啟動序列跑 `cat /README` 改跑 `cat /TESTDATA` 比對內容）、`echo ARG PASS`。

## 2. 硬連結（`link` syscall 實作）

`SYS_LINK`（18）現為 stub。inode 64B 尚有 20B reserved，取 4B 做 `nlink`（offset 44，舊映像檔讀到 0 視同 1，不破壞相容）。

- `link(old, new)`：old 須為 file（dir 拒絕，如 Unix）、new 不可存在；新 dirent 指向同 ino，`nlink+1`，persist。
- `unlink` 改：`nlink-1`，僅歸零時釋放 data blocks；dir 的 `.` 概念先不引入。
- `fstat` 回傳第 3 個字（`[kind, size, nlink]`，保持前 8B 相容）。
- 驗收：user 小程式或 shell 序列 `echo hi > /A` → `link /A /B` → `cat /B` 比對 → `unlink /A` 後 `/B` 仍可讀，印 `link PASS`；第二啟重驗（持久化一併覆蓋）。

## 3. 背景工作（`&`，純 shell 層）

- `sh`：行尾 `&` 切背景：fork+exec 後不 wait，記 pid 入 jobs 表（上限 8），內建 `jobs` 列出、`wait` 等全部（既有 `wait` syscall 語意是等任一子行程，夠用）。
- 前景 `wait` 行為不變；shell 退出（`halt`）前先等完背景工作。
- 驗收：啟動序列跑 `sleep`-類背景（`usertests &` + 前景 `ls` 交錯），不斷言時序，只斷言两者皆結束且無 PANIC，印 `bg PASS`。

## 4. on-disk 相容策略

- v0.3 kernel 必須能讀 v0.2 `mkfs` 產生的映像檔：新增欄位只用 reserved 區（`nlink`），讀到 0 視為 1；superblock 加 `version u32`（offset 44，舊檔為 0 視同 v1）。
- `mkfs` 寫 version=2 + 正確 nlink；`cargo test -p mkfs` 補新舊解析測試。

## 5. 順手（小、獨立）

1. `SYS_KILL`（8）實作基本款：標記目標，下次進 trap 即 `exit(-9)`；shell 內建 `kill <pid>`（pid 從 `jobs` 看）。不斷言時序，只測「kill 後 wait 回 -9」。
2. stdin 改 blocking 語意：`read(0)` 無資料時設 yield flag 並由 trap 尾切走（現為回 0 由 user 忙等），`cat` 不帶參數時可真正等鍵盤；`< /dev/null` 的 test.sh 行為不變（EOF 即回 0）。
3. mount-time bitmap 重建（fsck-lite）：superblock 加 `dirty` flag，`halt`/正常關機清 flag；mount 見 dirty 即掃全 inode 重建 bitmap 後繼續（不斷電一致性，只防 leak 誤判 ENOSPC）。

## 6. 非目標（仍不做）

- COW fork（風險高、效益低：user address space 小，全拷貝夠用，留待 v0.4 評估）。
- journal、uid/權限、網路、多 hart、indirect2。

## 7. 預估動工順序

1. argv（loader + user-lib Entry + 3 個 app + shell 切 token）。
2. nlink + link/unlink/fstat（mkfs + kernel 同步，host round-trip 先行）。
3. `&` + jobs（純 user 層，可與 2 並行）。
4. kill + stdin blocking + bitmap rebuild。
5. `test.sh` 新斷言（`cat ARG`、`link`、`bg`，第二啟重驗 link）。

## 8. 實作結算（與規劃的差異）

- argv：stack 布局為 `[sp]=argc, [sp+8..]=argv[]`，entry 讀 sp 傳 `main(argc, argv)`；`sys_exec` 先把參數拷出 user 記憶體才換位址空間（順序錯了會讀到新表的垃圾）。
- link 測試併入 `persist`（新檔分支順手做 link→讀→fstat nlink=2→unlink→nlink=1），不另開 app；`/TESTDATA` 保留給次啟 READ。
- kill 測試用 sh 內 fork 的 user-mode 自旋子行程（`yield` loop），時序確定；`pipe_test` 當受害者有競態。
- stdin blocking：現況（無資料回 0 + yield flag 由 trap 尾切走）已合要求，未改程式。
- fsck：mount 見 dirty 即重建 + 清 flag；`halt`（SYS_SHUTDOWN）亦清。首啟（mkfs dirty=1）印 `fsck: bitmap rebuilt`，次啟略過。
- `test.sh` 斷言增至：RW、mount、fsck、WRITE、link、cat ARG、hello-arg、bg、kill + 次啟 READ。
