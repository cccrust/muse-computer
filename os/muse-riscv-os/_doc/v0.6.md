# muse-riscv-os v0.6（已實作，`test.sh` 31 項全過）

延續 v0.4（UART RX 中斷 + blocking read）。v0.4 明確留白的兩項：**virtio-blk 完成中斷**（維持 polling）與 **UART TX 中斷**。on-disk 格式不動；syscall 號不動。

## 1. virtio-blk 完成中斷（核心）

現況 `fs/virtio.rs::submit()` 單 flight、純 polling（`used idx` 忙等，上限 20M spins）。

- `plic.rs`：加 `VIRTIO_IRQ=1`（QEMU virt 第一台 virtio 在 `0x10001000` 即 IRQ 1），priority=1、context1 enable bit1。UART（10）不動。
- `task`：加 `BLOCK_VIRTIO=3` + `wake_virtio()`（比照 `wake_stdin`）；加 `scheduler_active: bool`（`task::run()` 置 true，供 driver 區分 boot/運行期）。
- `virtio::submit()` hybrid 等待：notify 後先看 `used idx`（命中即走快徑，boot 期亦然）；未命中且 scheduler 已起 → `block_current(BLOCK_VIRTIO) + yield` 迴圈等 ISR 喚醒，附 tick 超時（500 ticks）回退 bounded-spin，保證 IRQ 丟失也不 hang。
- `virtio::on_irq()`：讀 `INTSTAT`，bit0 置位則 IRQ 計數器+1、`INTACK` 回寫、喚醒 virtio sleepers。
- `[TEST] virtio-irq PASS` 掛在 **claim 側**（`trap.rs` 首個 `claim()==VIRTIO_IRQ`），而非 INTSTAT 側——實測 submit 側（快徑/看門狗喚醒）通常先 consume+ack，INTSTAT 到 claim 時多半已清零，掛 INTSTAT 側會因競態永遠不印。
- `trap.rs` 外部中斷分發：`irq==1 → virtio::on_irq()`，其餘未知 IRQ 保持 claim+complete（消音）。
- 無 lost-wakeup 論證（單 hart、kernel 內 `SIE=0`）：check-idx 與 block 同處 trap 關中斷區間，ISR 只在 U→trap 入口跑；device 先完成則 idx 可見，後完成則任務已 Blocked、ISR/看門狗喚醒。
- **看門狗是必需的，不只是保險**：sleeper 在睡著時無法自己檢查 deadline（`timer::ticks() >= deadline` 只有被排程才跑得到），纯 ISR 喚醒在無其他外部 trap 的安靜 run 會餓死；故 timer tick 每次都 `wake_virtio()`（re-check：未完成則重睡），500-tick deadline 在此之上才有意義。

## 2. UART TX 中斷（核心）

現況 `uart::putchar()` 逐字节 polling（`LSR bit5` 忙等）。

- `uart.rs`：加 512B TX ring；`putchar` 改 enqueue + 置 `IER bit1`（THRE 中斷使能）；ISR 讀 `IIR` 分發：`0x2` → TX drain（THR 空且 ring 非空則寫，ring 空則**清 `IER bit1`** 防電平中斷風暴）、`0x4/0xC` → 既有 RX drain、`0x6` → 讀 LSR 消中斷；迴圈 64 次封頂。
- `putchar` 在 TX-IRQ 未使能前（`console::init` 早於 `trap::init` 的開機印字）走舊 polling 路徑；`trap::init` 內 `irq_enable` 後加 `tx_enable()`。
- 單 hart 可重入論證：kernel/ISR 的 putchar 臨界區只做短 enqueue（持鎖不 yield 不阻塞），且 kernel 內 `SIE=0` 使 ISR 不會插進 kernel putchar；ISR 內 `println`（如 Ctrl-C 訊息）走同一 enqueue 路徑。
- 首個 ISR 實際搬運（drain ≥1B）時印 `[TEST] uart-tx-irq PASS`（一次）。

## 3. 驗收（`test.sh`）

- `check "virtio-irq PASS"`（run1）：首個被 claim 的 virtio 完成中斷；決定性出現。
- `uart-tx-irq PASS` 斷言放在 **run3（`qemu3.log`）**：THRE 的傳遞只有在外部 trap 執行 claim pass 時才看得到；安靜 run（stdin=`/dev/null`）沒有 RX，THRE 即使在 PLIC pending 也沒有 claim 機會。run3 的 RX 流量（Ctrl-C + halt）強制 claim pass，實測決定性出現。
- run2 不動；既有 `virtio-blk RW PASS`（selftest，boot 期 polling）保留，證明雙路徑並存。

## 4. 非目標

- 多 flight / virtqueue depth>1 併發、DMA、MSI-X、多 hart（PLIC 只配 hart0 context1）。
- 16550 FIFO 深度調優、波特率設定（QEMU 虛擬串口無意義）。
- block cache 擴大/LRU（留待純效能版）。

## 5. 動工順序

1. `plic` IRQ1 + `task` BLOCK_VIRTIO/scheduler_active（純加法，QEMU 行為不變）。
2. `virtio` hybrid submit + on_irq + trap 分發（`cargo test` 不可測，全靠 QEMU log；先以 `virtio-irq PASS` 是否出現驗 ISR 接線）。
3. `uart` TX ring + IIR 分發（注意：改完首啟若洗版/靜默，優先懷疑 THRE 電平風暴 → 查 IER bit1 清除路徑）。
4. `test.sh` 2 斷言；全量 `./test.sh`。
