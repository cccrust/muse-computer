# muse-riscv-os v3.10（主線：upgrade 依賴 pin 重驗）

## 0. 動機

v3.3 留的已知缺口：`upgrade` 把包升到新版時，不檢查依賴者的
版本 pin——farewell 要 `hello=1.0`，hello 被升到 2.0 後依賴關係
靜默失配。本版補上：升級前重驗所有已裝依賴者的約束。

## 1. 語義

- `upgrade_one` 在確定目標版本後、動手裝任何東西**之前**：
  掃 `/pkg/*/manifest`（v3.1 起每個包都存一份），找出所有
  depends 提到本包的已裝包；逐個用 `ver_sat(新版, 約束)` 驗。
  任一不滿足 → `ctr: held by <other>` exit 1（第一個找到的；
  store、db、links 全沒動，原子性天然成立）。
- 無約束依賴（`depends: foo` 裸名）永遠滿足（任何版都行）。
- 自依賴跳過（自己不擋自己；循環依賴本來就裝不上去）。
- `upgrade`（全升）逐個走同一檢查。
- 非目標：自動降級依賴者、約束衝突的調解 UI（apt 會問，
  我們直接拒絕，寫死在這）。

## 2. suite（確定性設計：擋一次）

db 乾淨時（v3.6 段後）：

```
ctr install 10.0.2.2 8091 farewell   → pkg-installed farewell 1.0（+ dep hello=1.0）
ctr upgrade 10.0.2.2 8091 hello      → ctr: held by farewell
ctr remove farewell                  → pkg-removed farewell
ctr remove hello                     → pkg-removed hello
```

- test.sh +1 項（run1）：`held by farewell`（其餘行舊 marker）。
- 手動：`upgrade` 無約束依賴者時照常升（v3.3 段已覆蓋）。

## 3. 非目標（→ v3.11+）

約束調解、downgrade、依賴者自動跟升。
