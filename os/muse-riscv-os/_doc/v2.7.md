# muse-riscv-os v2.7（主線：CPU shares——比重公平）

## 0. 動機

配額三部曲還差最後一塊：v2.2 管「不能超」（內存 cap），v2.3 管
「超了就讓」（ceiling），但兩個都活著搶 CPU 時誰多誰少，沒人管——
默認先到先得。本版補比重：cgroup 帶權重，調度按虧欠選，
CFS 精神、子集實現（誠實邊界見 §4）。

## 1. vruntime（每窗口，整數，無浮點）

- `CG_SHARE[256]` atomics（`SYS_CGSETSHARE=54(id, weight)`，
  1..1000，否則 -1；0 槽位=默認權重 1——零初始化構造正確）。
- 記賬沿用 v2.3 窗口（100-tick，`CG_WIN_USE`）：組 vruntime =
  `win_use * 1024 / eff_weight`（eff 默認 1）。窗口翻轉清零
  （跨窗口不背債——ceiling 同紀律，短暫不公可接受，寫死）。
- 與 ceiling 正交：pass 1 先跳超額（ceiling 語意不動），
  剩下里面挑 vruntime 最小的；pass 2（work-conserving 兜底）不動。
- 默認全組等權 ⇒ min-vruntime = 窗口內跑得最少的 ⇒ 近似公平 RR，
  舊行為大體延續（v2.3 cpu-order 的 free 組內公平性不變，裕度不動）。
- 不餓死：vruntime 是單調虧欠制——餓著的任務 vruntime 不漲，
  遲早最小（與 ceiling「趨近 0」不同，這是 floor 側的傾向；
  但傾向不等於可斷言，見 §4）。

## 2. best-pick（pick 三處同規則，v2.3 隊形延續）

- `pop_valid_locked` / `find_next_pass` 的 skip_quota pass：
  從「首個可用即回」改為「掃完取 vruntime 最小」。
  不中選的一律 stash（超額的照舊 stash），選定後按遇見順序推回——
  隊列相對順序不亂，只是出隊選擇加權。stash 上限（32/64）滿了
  就地推回（舊 pattern，不丟任務）。
- 並列（vruntime 相等，常見於開窗瞬間）：先遇先得 = FIFO，
  確定性保留。
- Races 往寬鬆走（Relaxed 讀計數，ceiling 同款聲明）：
  最壞一窗內偏一點，不餓死不斷言。
- 跨核：窗口計數全局共享（atomics），各 hart 選各自最小——
  不是全局最優但是收斂（SMP 啟發式，寫死；要全局最優得中心隊列，
  那是推倒 v1.1，v2.7 不碰）。

## 3. `cgtest` share_phase（併入，不新增 suite 項）

- A 組（share 8）4 hog vs B 組（share 1）4 hog，同等功，全部 uncapped
  （ceiling 不插手，純比重對決）。hogs 數是 hart 數的 2 倍——每核永遠
  有得選（oversubscription 紀律的輕量版；尾盤 hog 自然減少不影響，
  因為只斷言第一個）。
- hog 不 yield（純 spin + fence 防 DCE，`SPIN_N` 橫跨數百 tick）：
  yield 會以 ~MHz 調度而 vruntime 以 100Hz 記賬，信號在 tick 間凍結、
  同一任務會被連中（pinning）。純 spin 把 pick 對齊到 timer tick
  （每次 pick 計數都是新鮮的）。
- 斷言（completion，不 order，理由見 §4）：API 邊界（壞 id/權重），
  之後全收——驗 code、驗數；15s 上限。
- FAIL 理由獨立命名（`share-timeout`/`share-code`/`share-count`/…，
  與 cpu-* 區分）。
- 為何不另起 user 程序：v2.3 前例——併入 cgtest，test.sh 項數不動
  （73 項）。

## 4. 誠實邊界（寫死，不修——本節是 v2.7 最重要的部分）

- **不斷言順序**（v2.3「保 ceiling 不保 floor」的 shares 版）：
  每 hart 釘住本地隊列（非空不偷），lo hog 一旦獨佔一核就全速跑完——
  權重再大也追不回（實測：smp4 上 lo 先收完，8:1 照輸；
  -smp 1 反而過，單隊列下偏好確實生效——機制是對的，
  觀測是不可能的）。first-finish 測的是隊列運氣，不是 shares。
  要確定性順序得靠 exclusion（二進制開關，如 ceiling），而 min-vr
  是公平制：餓不死任何人，也攔不住獨佔者。用順序斷言語義就是錯的。
- completion 斷言的真值：方向寫反（pick-MAX）會餓死最小者直到超時；
  pick 路徑掛掉（無窮迴圈、stash 丟任務）會超時；API 錯會直敗。
  first-fit（無視權重）也能過——這是坦白記載的盲區，
  權重公式由 host 單測精確鎖定（見下）。
- `vruntime` 數學由 host 單測鎖定（`host-tests`：8:1 精確比值、
  min 方向、默認權重、零除守衛——逐位元確定性，無時序）。
- 保證排序，不保證精確比例（8:1 不承諾 8:1 用時；跨核啟發式+窗口
  語意下精確比例本來就不存在——要 CFS 級精確得重寫 v1.1 隊列）。
- 保證「餓不死」（min-vruntime 單調），不保證 latency 上限。
- 權重運行時可改（`cgsetshare` 隨時），改的當窗可能偏一點。
- floor（保底份額、CFS bandwidth）仍是 v2.8+ 議題；本版是 shares
  （比重），不是 reservation（預留）。

## 6. 非目標（→ v2.8+）

  權重繼承以外的動態調整（auto-share）、CPU floor/reservation、
  CFS bandwidth、IO 權重、netns/veth、overlayfs、registry 認證、
  volume、cgroupfs、OOM-killer、`pivot_root`。
