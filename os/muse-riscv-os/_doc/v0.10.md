# muse-riscv-os v0.10（已實作，`test.sh` 39 項全過）

方向：讀快取放大 + 真 second-chance + readahead + 統計。**維持 write-through**（見 4）。

## 1. 快取放大 + 置換

現況 8 槽、號稱 clock 實為 round-robin（無 ref bit）。

- `NSLOT 8 → 64`（32KB `.bss`，可接受）。
- 每槽加 `ref: bool`：命中置位；miss 掃描時首輪只清 ref、次輪才驅逐（真 second-chance）。
- 寫入維持 write-through（device 先寫、快取同步更新；`HAND` 改為 second-chance 掃描選 victim）。

## 2. 順序 readahead

- miss 讀 `n` 時，若 `n+1` 未命中，順手讀入（ELF 連續區段、目錄掃描皆順序，讀 miss 減半期望）。
- 只做 1 塊（快取污染可控；`NCAP` 邊界檢查）。

## 3. 統計 + 關機印出

- `HITS / MISS / DEV_RD / DEV_WR`（blk 層計數；`DEV_*` = 實際 virtio I/O 次數）。
- `blk::sync()`（現為空概念的落點）：遍歷（write-through 下無 dirty，無事可做——保留函式供未來 write-back），印 `[FS] cache hits=H miss=M dev_rd=R dev_wr=W`；`SYS_SHUTDOWN` 呼叫。
- `test.sh` run3（`halt` 走正常關機）斷言 `check "cache stats"`——行內含該子串即可（數字隨 workload 浮動，不斷言數值）。

## 4. 為何不做 write-back（記錄決策）

`test.sh` run1 結尾是 `timeout` 砍 QEMU（≈ 斷電），run2 直接重用同一 `fs.img` 驗持久化。write-back 下 kill 時的 dirty 塊永遠丟失 → `persist READ` 必 FAIL。write-back 唯一安全點是縮短 kill 窗口外的定期 flush，但仍是競態。只有當測試流程改為「正常 halt 關機後再重啟」（如 run3 模式）才能做 write-back；留待測試框架支援後再議。

## 5. 非目標

- write-back/journal、壓縮、multi-queue、cache pin。

## 6. 實測

一次完整 `test.sh` run3（autorun 全套 + 互動關機）：`hits=8416 miss=1537 dev_rd=3045 dev_wr=18`，命中率約 84.5%。`dev_wr` 僅 18（superblock dirty 旗標等元數據寫入多為 write 合併命中）。
