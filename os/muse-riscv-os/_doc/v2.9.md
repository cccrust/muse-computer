# muse-riscv-os v2.9（主線：容器可觀測——logs / exec / 槽位回收）

## 0. 動機

v2.4–v2.8 把容器跑起來了，但三個完整性缺口：

1. `-d` 容器是黑盒輸出：stdio 繼承 console（`ctr` main.rs，
   `stdio inherited`），事後看不到 log。
2. `-d` 容器是黑盒進程：跑起來後再也進不去（`ctr exec` 不存在；
   kernel 也沒有 join-ns 原語）。
3. 槽位只增不減：ns 靠 v2.4 fork 期復用擋住了無界增長；cgroup
   槽位 push-only（256/boot 上限），反覆 run -d/stop/rm 會漏光——
   v2.4 曾試 cg 復用又回退（見 §3），本版用對的做法重做。

本版無新隔離層——純可觀測 + 回收。三件互相獨立，共用 test 樁風格。

## 1. 語義

### 1.1 `ctr logs`（後台 stdio 落盤）

- `run -d`：parent 在 fork **前**以 `O_CREATE|O_TRUNC` 開
  `/ctr/<name>/log`（絕對路徑，chroot 前；開檔順序在 cgcreate
  之前——失敗直接 exit 1，無殘留）。child 繼承 fd，chroot/chdir
  後 `dup2(log,1)+dup2(log,2)` 再 exec；parent fork 後關自己的
  copy。每次 run -d 截斷重開（與 `.pid` 覆寫同紀律）。
- 前台 run：不開檔，stdio 繼承，行為逐位元同舊。
- `ctr logs <name>`：把 log 倒到 stdout。liveness 不要求
  （stopped 也能看，docker 同款）。無檔 → `ctr: no log` exit 1。
- `ctr rm`：零改動（`rm_all` 遞迴，log 跟著走）。
- 非目標：rotate/截斷策略、follow（`-f`）、stderr 分流。

### 1.2 `ctr exec <name> <prog> [args...]`（進運行中容器）

```
ctr exec life /bin/echo hello-from-exec   → hello-from-exec（exit code 直通）
```

- `read_state` + `state_alive`，否則 `ctr: not running` exit 1
  （與 `no such container` 區分的新 marker）。
- fork；child：`nsenter(pid)` → `cgenter(cg)`（legacy cg==0 照進，
  root 無害）→ `chroot(/ctr/name)` → `chdir(/)` → `exec`；
  任一步失敗 loud + exit 127。parent：wait 轉 exit code（同前台 run）。
- 新 syscall `SYS_NSENTER=55`：`nsenter(global_pid)`——current 加入
  目標的 ns（`p.ns = t.ns`，`lpid = next++`，與 fork-into-ns 同規則）。
  拒絕：目標不存在、目標在 root ns（ns 0 加不加都是逃逸口；唯一
  合法用戶是 root ns 的 `ctr exec`——扁平權限模型，寫死在這）。
  zombie 目標接受（無害；`ctr exec` 前已有 state_alive 把關）。
- prog 解析 + argv 與 cmd_run 共 helper（toks 7→16，順手與
  kernel-16 對齊；v2.8 argv 教訓）。

### 1.3 cgroup 槽位回收 + ns 可觀測

- ns：v2.4 fork 期復用已在（alloc+occupancy 同一 sched_lock，
  無 create-then-enter 視窗——sound，無需重做）。本版只加可觀測：
  halt 行 `[NS] ns=N`（與 `[CG] groups=N` 並列；N 是高水位，
  存在性斷言如 v2.3 註記）。
- cg：reuse-on-create（ns 同款 lazy 式，不碰 exit/reap 路徑）：
  - `Cg += { used, reserved }`。`used` = 自上次分配後曾被佔用
    （fork 繼承 / cgenter 成功置位；分配/復用交接時清零）。
    fresh 槽 used=false——**create-then-enter 模式永不誤合併**
    （v2.4 回退的教訓：cgtest 先建 cap 組、子後進入；若復用
    「無人」槽，cap/free 兩組會塌成一槽，cpu-order FAIL）。
  - `reserved` = 交接中。cgenter 拒 reserved 槽（mid-reset 不可進）。
  - 交接協議（鎖決不嵌套：sched→放→ALLOC→放→sched）：
    sched 下找 `!reserved && used && 無 proc 引用` → 掛 reserved →
    出鎖後 `cg_use(id)` 必須為 0（否則解掛、換下一個；cgenter-away
    殘留幀的唯一正確處理）→ 清 CPU/share atomics + `lim=0` →
    回鎖設 parent、used=false、reserved=false → 出鎖後套 requested
    limit（沿用既有 `set_cg_limit` 流程）。
  - 候選用盡 → 走既有 push 路徑（256 上限不動）。
  - 併發：reserve 先到先贏；handoff 無睡眠，不卡人。`cgkill` 落在
    reserved 槽上回 0（無人，empty 探針語意不變）；`cgset*` race
    採 last-writer-wins（既有語意，不擴大）。
- 非目標：Vec shrink（索引即身份，刪不得）、use_ 非零槽的阻塞
  等待（跳過即正確）、cgroupfs、OOM-killer。

## 2. suite（確定性設計：markers + 上限反證）

- logs（新名 `logtest`，不碰 life；linger/sleeper 故意零輸出，
  用 `/bin/echo` 當輸出源）：
  `ctr logtest` → `ctr run -d logtest /bin/echo hello-from-log`
  → `ctr logs logtest`（`hello-from-log`）→ `ctr rm logtest`
  （`removed logtest`）。
  echo 瞬退的 pidinfo race：parent fork→pidinfo 無 yield，child 需
  完整 exec+write+exit+init-reap 才能消失，實務不可能輸；輸了也
  loud（exit 1），非靜默。
- exec（life 還活著時，插 `stop life` 之前）：
  `ctr exec life /bin/echo hello-from-exec`（`hello-from-exec`）。
- cgreuse（`cgtest` 內新段，確定性上限反證）：
  300×{ `cgcreate` → fork child `cgenter`+exit → `waitpid` reap }，
  全成功則 `cgreuse PASS`。無回收時第 ~256 個 create 回 MAX（-1）
  → loud FAIL。child 必須真 enter（occupancy，否則永不可復用）
  且 parent 必須真 reap（zombie 仍佔槽）。
  成本：300 fork（child 不 exec），秒級。
- test.sh +5 項：`hello-from-log`、`removed logtest`、
  `hello-from-exec`、`cgreuse PASS`（以上 run1）、`NS] ns=`
  （run3 halt 行存在性，與 `[CG] groups=` 同位置）。
  舊測項零退化（重點：前台 run 無 log 檔；不傳 exec 時 ns/cg 行為
  不動；`[CG] groups=` 行保留）。

## 3. 驗收

- `./test.sh` 全綠，零 `PANIC`/`FAIL`，連跑 2 輪。
