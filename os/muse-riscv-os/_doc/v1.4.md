## 0.1 判決（已執行，結論：冷，不拆鎖）

- **吞吐對照**：同機器背靠背，`stress` 所在全 autorun，smp1 ≈ smp4 ≈ 7s。
  4 核沒有變慢（大鎖不是瓶頸），也沒有變快（autorun 本質串行）——
  無論如何都沒有「鎖導致的擴展性問題」需要修。
- **miss/acq 讀數**：smp1 恆 0/1.4億（單核無競爭，計數器機制自證正確）；
  smp4 在 12%–79% 間劇烈浮動，且與 MTTCG host 負載正相關。結合代碼審查，
  主導項是 `waitpid` WouldBlock 輪詢（父無他任務可跑時立刻重 picked 自己，
  每秒數十萬次穿過 sched 鎖）——拆鎖對此零作用（PROC 鎖照樣被 hammer）。
- **結論：COLD**。鎖拆分無限期封存。真正該做的是把輪詢改成真阻塞
  （`BLOCK_WAIT`，見 §1），它同時是 dominant waste 的根治和未來判決數據
  的去污。本版執行之；TCP/journal 按原計劃退回 v1.5。

## 1. BLOCK_WAIT（判冷分支的執行：小而準）

- 新阻塞原因 `BLOCK_WAIT = 5`（`task/mod.rs`）。
- `waitpid` 慢路徑：原地 `yield`（全速空轉）改為**同臨界內**標記
  `Blocked/WAIT`（與 zombie 檢查同一把鎖，無 lost-wakeup），照樣回 `-2`——
  用戶態重試協議零改動（init/sh/usertests/stress 的 `-2` 迴圈照跑）。
- `exit()`：置 Zombie 後，若父 `Blocked/WAIT` 則 `Runnable` + 入隊
  （exactly-once；只認 `blocked_on == WAIT`，stdin 阻塞的 sh 不會被誤喚）。
- 喚醒路徑全覆蓋：kill/自然退出一律經 `exit()`；`WNOHANG`／無子／已收割
  三條快速路徑不碰。
- 驗收：suite 全綠×2（init/sh respawn、孤兒收割語意不變即證），且
  `contention` miss/acq 下降至少一個量級（預測；數字寫進提交訊息）。

### 1.1 附帶修復：idle 停在 KERNEL_ROOT（v1.2 teardown 的潛伏 bug）

- 症狀：teardown 上線後偶發「U 態從 kernel VA 取指」（sepc 落在
  `wake_sleepers`/`exit` 等調度函數內），且死掉的 pid 會再 fault 一次。
- 根因：idle 的 hart 帶著上一個 task 的 satp 睡 `wfi`；該 task 被收割、
  root 回收重用後，下一個 timer trap 經垃圾表走 kernel 映射，當場 fault；
  嵌套 trap 再把 kernel sepc 存進用戶 TF，屍體看起來像在跑。
  v1.2 以前從不釋放 root，所以從沒爆。
- 修：`idle_on_hart` 先 `activate(KERNEL_ROOT)`（不朽、含 idle 所需全部映射）
  再 sret。另加 `exit()` REEXIT 探測 + `switch_to` DUP-SWITCH 拒入（皆靜默，
  suite 照跑）。

- **判冷**（`contention` 相對 schedule 次數可忽略，或 wall-clock 隨核數線性）：
  不拆鎖。本版轉做 TCP 起步或 journal（見 §3），鎖拆分無限期封存。
- **判熱**（`stress`/net 負載下 `contention` 佔比高，或 4 核跑輸單核同測項）：
  執行 §1 的拆分方案。

預設不寫程式也是一種結論；本檔兩條分支都備好，判決當天即開工。

## 1. 拆分方案（封存：判冷未執行，保留作萬一哪天判熱的施工圖）

### 1.1 鎖拆分

- `PROC` 鎖：`procs`、`next_pid`、`current[4]`、`yield_flag[4]`、`idle[4]`。
- `QLOCK[4]`：各管 `queues[h]`；**鎖序 `PROC` → `Q`，一次只拿一把 `Q`**。
- 全 audit 點：`enqueue`/`pop_valid`/`pick`/`schedule_point` requeue（直推，
  v1.1 §8 教訓）/`find_next`/`run_on`/`switch_to`/`waitpid` purge/
  `wake_*`/`kill_with`/`kick_idle`（`PROC` 後按 hart 序拿 `Q`）。
- v1.3 的 net 程式碼一併納入審計（RX/TX 臨界、`wake_net` 入隊點）。
- DUP 探測器、exactly-once、requeue 直推三鐵律維持。

### 1.2 驗收（判熱分支）

- `./test.sh` 全綠（56 項），零 `PANIC`/`FAIL`，**連跑 3 輪**（鎖工抖動大）。
- `steals>0`、`ipi PASS`、`reclaim PASS`、`net PASS`、`stress DONE` 皆在。
- 人工：同機器對比 v1.3 的 `contention` 數值顯著下降（寫進提交訊息，不卡版）。

## 2. 驗收（判冷分支：BLOCK_WAIT，已執行）

- `./test.sh` 全綠（56 項），零 `PANIC`/`FAIL`，連跑 2 輪。
- `steals>0`、`ipi PASS`、`reclaim PASS`、`net PASS`、`stress DONE` 皆在；
  init/sh respawn 與孤兒收割語意不變（suite 即證）。
- 實測 payoff（同機器背靠背 run3）：取鎖總數 16M → 0.25M（**60×+**），
  miss/acq 比值上升（0.7 → ~10，突發碰撞特性）但總量崩塌——判決確認：
  dominant waste 已除，拆鎖更無必要。

## 3. v1.5+ 候選（按需排序，另立版本檔）

- journal（crash 一致性；`stress` + 斷電測試是驗收）。
- ASID 管理（接 `activate`/`exec`/teardown，省 RFENCE 全刷）。
- affinity syscall、`ping`（ICMP）、swap。
