# muse-riscv-os v1.2（主線：exit 記憶體回收，堵住 leak）

## 0. 動機

v1.0/v1.1 的 `waitpid` 收割只把 `procs[c]` 置空，從不釋放該進程的 frame：
用戶頁、頁表頁、`tf_pa` 全漏（為避 ASID-0 殘留而留，見 `v1.1.md §4`）。
`test.sh` 跑完就關機所以沒爆；任何長期跑、fork 頻繁的負載必 OOM
（`alloc_frame().expect("oom")` 直接 PANIC）。本版把回收做對，
RFENCE 框架 v1.1 已鋪好，這裡接上即可。

## 1. 設計

### 1.1 所有權確認（動工前 audit，不寫碼先證）

- `clone_user` 全拷貝（`pagetable.rs`：逐頁 `alloc_frame` + `copy_nonoverlapping`），
  無共享 → 每個 root 擁有的 frame 可由頁表 walk 完整列舉。
- 用戶 root 內只有 U 葉 + TF 的 S-only 映射（`new_user_space` 不混入 kernel
  全局表——若 audit 發現有共享 kernel 表頁，teardown 必須跳過非 U 葉；
  TF frame 另由 `tf_pa` 釋放，walk 內同樣跳過非 U）。
- `fork` 的中間表頁（`ensure_next` 新配）亦屬該 root，一併回收。

### 1.2 `mem::free_user_space(root)`（`mem/mod.rs` 新函式）

- 結構鏡像 `clone_user`：走 L2/L1/L0，`dealloc_frame` 每個 U 葉 frame、
  每個中間表頁、最後 root 本身。跳過非 U 葉（TF 映射）與非 V 項。
- 不取 sched 鎖（純 frame 分配器鎖；呼叫點見下）。

### 1.3 收割點（`task/mod.rs` `waitpid`）

- 找到 zombie 後：鎖內取出 `(root, tf_pa)` → `procs[c] = None` → 四隊 purge
  （沿用 v1.1）→ **解鎖後** `free_user_space(root)` + `dealloc_frame(tf_pa)`
  + `pt::remote_flush_all()`（釋放的 frame 會重用，ASID 全 0 必刷）。
- 解鎖後釋放：slot 已消失，無人能再碰該 root；亦避開 sched→frame 鎖序問題
  （`new_proc` 已是 sched→frame 序，這裡根本不持 sched 鎖，更乾淨）。

### 1.4 孤兒 reparent（同版必做，否則回收覆蓋不全）

- 現況無 reparent：父先死，子的 `parent` 懸空，沒人 `waitpid` 它 → zombie
  永不收割 → 照漏。`exit()` 內把活著的 children 過繼給 init（pid 1）。
- init 用戶端已是 `wait` 迴圈（`user/init`：respawn sh 前會收割——動工時核實；
  若無，補 `waitpid(-1)` 迴圈）。

### 1.5 爭用計數器（順手，非主題：為 v1.4 的鎖決策提供數據）

- `sync.rs` 加 `SpinMutex::lock_counted(&self, miss: &AtomicU64)`：
  CAS 失敗一次記一次；只換 `SCHED` 鎖的 callsites（熱路徑 UART/TX 不動）。
- halt（`SYS_SHUTDOWN`）印 `[SMP] contention sched=<miss>/<acq>`
  （miss=失敗 CAS 總數，acq=取鎖總數；miss/acq 即判決用熱度）；
  `test.sh` 斷言存在性。
- 這個數字是全計劃最重要的一行 log：v1.4 靠它決定拆不拆鎖。
- 讀數警告（v1.3 實測）：`miss/acq` 在同機器不同輪間劇烈浮動（12%–67%），
  主因是 `waitpid` WouldBlock 輪詢——父進程 yield 後若無他任務可跑會立刻
  重 picked 自己，形成穿過 `schedule_point` 的全速空轉（每秒數十萬次取鎖）。
  因此絕對值無意義，**判決只看同機器、同負載、背靠背跑的相對差值**；
  要根治輪詢應把 `waitpid` 慢路徑改真阻塞（`BLOCK_WAIT` + `exit` 喚醒父，
  v1.5 候選，不在本版動）。

## 2. user/test

- 新 syscall `SYS_MEMSTAT = 36`：回傳當前 free frame 數（`frame::free_frames()`
  需新增；分配器內部計數，不掃 bitmap）。
- 新 `user/reclaim_test`（workspace/mkfs/`embed.rs`/`run.sh`/`test.sh` 接線沿用
  `smp_test` 前例）：讀 free 基線 → 20 輪（fork 子進程 `sbrk` 1MB 全觸碰後
  `exit(0)`，父 `waitpid` 收割並校驗 code）→ 再讀 free；`基線-收尾 < 64` 印
  `[TEST] reclaim PASS` 否則 FAIL（64 框住頁表/零散開銷；20MB 累積分配在舊碼下
  必漏 5000+ frame，閾值兩邊都穩）。
- `test.sh` run1 加 `check "reclaim PASS"`；sh autorun 加跑
  `/bin/reclaim_test`（放在 `smp_test` 之後；耗時約數秒，120s 預算內）。
- 新 `user/stress`（燒機器，回收與鎖計數共用）：4 核同時 fork/exit/pipe/
  sbrk 風暴 30 秒，只求不死，結束印 `[TEST] stress DONE`；`test.sh` 斷言存在
  （53+2=**55 項**：reclaim + stress）。它同時是 v1.4 判決的負載來源。
- OOM 語意不變（`expect` PANIC；`test.sh` 的 `no PANIC` 斷言即覆蓋；
  真正的 ENOMEM 回傳是 non-goal）。

## 3. 驗收

- `./test.sh` 全綠（55 項），`qemu*.log` 零 `PANIC`/`FAIL`，連跑 2 輪。
- `reclaim PASS`、`stress DONE`、`contention sched=` 穩定；附帶觀察：
  `steals=`、`ipi PASS` 不退化。
- 舊碼對照實驗（可選）：reclaim_test 在 v1.1 內核上跑應 FAIL（證明測試有效）。

## 4. 非目標（→ v1.5）

- COW fork、swap/demand paging 的換出、ENOMEM 優雅回傳與 OOM killer、
  slab 細粒度分配器、journal（v1.5 候選）。
