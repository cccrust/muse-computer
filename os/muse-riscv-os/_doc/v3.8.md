# muse-riscv-os v3.8（主線：guest 函式庫——首批上架 crates.io 的包）

## 0. 動機

v3.2 的管線能編 binary crate，但 crates.io 上至今零個 guest 包——
生態的第一步是有人先放兩個真正有用的 library 上去。本版寫兩個
（`guest-args`、`guest-fmt`，名子已查空），主人親自 `cargo publish`。

## 1. 語義（兩個 crate 的 API 凍結點）

- 位置：`user-lib/guest-args/`、`user-lib/guest-fmt/`（獨立 crate，
  自帶 `[workspace]` 脫離主 workspace，零依賴、core-only）。
  `user-lib` 本體加 `exclude = ["guest-*/"]`（發布時不夾帶）。
- `guest-args`：argv 切片上的小工具（不碰 user-lib，純邏輯）：
  - `split_eq(arg) -> (name, Option<(ver, u8)>)`：`foo`/`foo=1.0`/
    `foo>=1.0` 三態（ctr 手刻三遍的邏輯，收攏第一案）。
  - `parse_dec(s) -> Option<usize>`：全數字才認（leading-garbage
    拒收；ctr 舊版只認前綴數字的寬鬆版不收）。
  - `parse_mem(s) -> Option<usize>`：`N`/`K`/`M`/`G` 後綴轉幀數
    （ctr v2.8 語義：裸數即幀，K/M/G 按 byte 上取整）。
- `guest-fmt`：無分配格式化（寫進 caller buffer，回長度）：
  - `fmt_dec(buf, v)`、`fmt_hex(buf, v)`、`fmt_oct(buf, v)`。
  - `push_dec`/`dbg_num`（ctr/sh 手刻 N 遍的，收攏第二案）。
- 兩 crate 皆 `#[cfg(test)]` NIST/邊界向量 + `cargo test` 進
  test.sh 快門。in-guest 正確性走 kernel `lib.rs` 同款 mirror 紀律：
  純邏輯 host 證、riscv 部署（`jnl_crc` 等前例；分支簡單算術，
  codegen 無風險，寫死在這）。`fortune` 本版不動（無數字輸出可換，
  硬接是造假；ctr/sh 採用重構另立版，見 §3）。
- 上傳清單（主人執行，本版只備料）：兩 crate `description` +
  MIT + README + `cargo package --list` 能過；名子已查空（2026-09，
  `guest-args` / `guest-fmt` 皆 404）。

## 2. suite（確定性設計：host 向量 + 零 guest 擾動）

- `cargo test -p guest-args -p guest-fmt`（快門；失敗即 `PASS=0`）。
- guest 側零改動、零新 marker（備料版；106 項維持）。
- 手動：`cargo package --list --allow-dirty -p guest-args`
  （樹髒是常態，只驗備料齊）。

## 3. 非目標（→ v3.9+）

第三個庫（`guest-env`？等有人喊）、`cargo publish` 本體（主人帳號）、
ctr/sh 改用新庫重構（能跑就別碰，大重構另立版）、no_std 以外的依賴。

## 4. 驗收

- `./test.sh` 全綠（106+0=**106 項**，無新增斷言——本版是備料版），
  零 `PANIC`/`FAIL`，連跑 2 輪。
- 舊測項零退化（重點：guest 零改動；user-lib 發布內容
  不變——exclude 生效，用 `cargo package --list -p user-lib` 驗）。
